# M2：真实模型与知识库

范围：在 M1 已有项目、Agent 发布、会话和独立 Runtime 上增加可使用的托管知识库。用户提供三种 Qwen 服务，并确认向量请求可通过 `dimensions` 配置；本次验收使用 `qwen3-embedding-4b` 的 1024 维，不把先前探测到的 2560 维当作模型固定值。

## 交付行为

- 模型管理区分对话、向量、重排；向量维度可选，通过请求参数发送。模型配置不可原地修改，避免既有发布和索引悄然变化。API 不返回保存的密钥。
- 知识库固定向量模型、可选重排模型和分段配置。指定维度时从创建开始固定；未指定时从首个有效批次固定。所有后续入库与查询均检查维度。
- 上传 UTF-8 TXT / Markdown，保存文件名、原文、SHA-256 摘要和状态。相同内容去重；失败后显式重试，生成新任务。删除原文、分段，终止进行中的入库。历史会话引用和历史检索任务是独立的已保存副本，不承诺随源文档删除。
- 独立 Runtime 主动领取任务，用 Mastra `MDocument` 递归分段并批量调用真实向量接口。租约、超时和写入栅栏由控制面检查。完整提交后原子变为可检索；失败或丢失租约的中间分段不可检索并清理。Runtime 没有数据库凭据。
- PostgreSQL + pgvector 保存向量，按知识库和当前 ready 文档进行精确余弦召回。重排在 Runtime 调用 `/rerank`，检索结果保留文档、片段、内容摘要和分数。
- Agent 发布固定知识库绑定和模型配置；语料使用最新成功入库的文档。运行凭据只含已发布依赖。`knowledge_search` 只能查询本次发布授权的知识库。模型自主调用后返回来源编号，控制台提供可展开的来源正文。
- 管理 API 继续限定平台用户；应用凭据通过已发布 Agent 使用知识库。新增 API 与 TypeScript SDK 均从 Hono/Zod OpenAPI 通过 Hey API 生成。

## 当前边界

本切片仅支持平台托管文本知识库。PDF / Office / OCR、可视化文档处理工作流、私网知识库、访问许可与删除副本治理、成员细粒度权限和检索质量评测尚未交付。后续仍沿用 FlowGram 编辑、Mastra 执行以及混合资源位置的既定主线。

当前预算：每份文档最多 20 万字符、256 个分段；浏览器文件上限 800 KB；知识库最多 200 份有效文档、10,000 个分段。每批 8 段，候选召回最多 20，返回最多 10；单知识库最多 10 个进行中的测试检索。任务期限 5 分钟，Runtime 租约 20 秒，每 4 秒续租。每个 Runtime 当前并行执行一条 Agent 任务和一条知识任务。

当前采用有范围过滤的精确检索。HNSW、混合检索、模型健康探测、横向扩容和容量目标验收另行实施；预算不等于吞吐保证。真实模型合成样例仅证明协议和执行闭环，不能替代业务回答质量验收。

## 本地升级

Compose 的 PostgreSQL 保留原有 16 Alpine 基础镜像及数据卷，通过固定 pgvector 0.8.6 源码及 SHA-256 构建扩展，避免直接把 Alpine 数据卷迁入另一发行版。升级前应停止本项目服务并备份数据库，然后执行：

```sh
docker compose up -d --build --wait postgres
pnpm db:migrate
pnpm sdk:generate
pnpm build
pnpm preview
```

源码：[assistant-ui Markdown](https://www.assistant-ui.com/elements/markdown-text)、[pgvector](https://github.com/pgvector/pgvector)、[Mastra MDocument 分段 API](https://mastra.ai/reference/rag/chunk)。pgvector 的向量存储与近似索引维度限制不同；当前精确检索保留完整浮点向量。

## 验证记录

真实服务验收已完成：Qwen 对话调用求和工具得到 120；三份合成文档 1024 维入库；重排首位命中设备规格；Agent 回答 24GB GDDR6 和 GPU-A5000-24，并带实际分段引用。

2026-09-08 本地验证：

- `pnpm test` 9 组通过；其中知识库集成测试通过生成 SDK 和 HTTP Runtime 验证超过一个批次的 Mastra 分段、dimensions 参数、乱序 embedding index 对齐、重排、异常维度与删除。
- Store 回归覆盖发布固定、绑定范围、取消后的检索拒绝、原文保留、任务去重、失败重试，以及持有知识库锁跨过租约截止后拒绝写入。
- `pnpm typecheck`、`pnpm lint`、`pnpm build`、`pnpm sdk:check` 通过；AntD CLI 无问题。构建仍提示大型分块（聊天约 685 KB、AntD 约 1,039 KB，压缩前），尚未完成首屏性能专项验收。
- 构建后的控制台完成模型类型/1024 维配置、创建知识库、真实文件上传、ready 状态、分段预览、向量检索、重排结果及删除。数据库复核上传文件 BOM、缩进、末尾换行与 SHA-256 均保持一致。
- 知识库页面在 1440/1024/768/390 宽度、聊天在 390 宽度验证无整页横向溢出；手机可打开导航和查看来源。聊天使用 assistant-ui Markdown 组件呈现列表、表格和代码，禁用原始 HTML 和模型输出中的远程图片自动加载。
- SDK 打包后在独立目录安装，以普通 Node.js 导入。AppID + AK/SK 实际调用已发布知识库 Agent，返回正确内容与来源；应用凭据访问知识库管理接口被拒绝。
- 重启控制面、Runtime 和控制台后，文档/向量以及历史回答仍可读取。验收均使用合成资料。
- 两条独立代码审查发现并关闭了“事务时间导致过期租约被接收”和“正文 trim 导致原文/摘要改变”两项问题；相应回归已通过。

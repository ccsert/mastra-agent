# M3：远程 MCP 业务工具

状态：本地开发验收完成（2026-09-08）。沿用已确认的工具治理规则，在 M2 正式平台上补充远程 MCP 只读能力接入。

## 本次交付范围

管理用户登记项目内的 Streamable HTTP MCP 服务，凭据加密保存。独立 Runtime 主动领取发现任务，完成协议初始化和分页 `tools/list`，控制面保存发现快照。发现不执行工具，不把远端 annotations 当作授权。

用户查看能力说明和输入/输出 schema，明确确认只读性质并设置平台调用名后导入不可变工具。工具绑定 Agent 并随发布固定；远端契约变化、能力消失或服务停用时拒绝后续调用。新发现与导入形成新资源，旧发布不自动漂移。远端实现是否改变不能单凭 schema 判断，业务服务仍需自身版本化。

同服务、同契约、同平台调用名重复导入返回原工具；使用不同别名生成独立工具，允许来自多个服务的同名能力共同绑定。审阅弹窗固定 descriptor 和 discoveryId，列表刷新不会改变待确认对象。当前工具资源不可变，后续版本目录与别名管理不在此切片交付。

Runtime 使用官方 MCP TypeScript SDK，调用前重新读取当前授权和独立目标凭据，校验远端能力与固定快照一致，并校验输入及结构化输出。当前仅返回文本和 JSON，其他内容类型明确报不支持。平台身份令牌不会转发至 MCP。

管理页提供登记、发现状态、能力审阅、导入、停用/启用与凭据轮换。管理 API 和 TypeScript SDK 从 OpenAPI 生成；应用凭据调用已发布 Agent，不能通过管理接口登记或导入能力。

## 验收与边界

使用合成订单 MCP 服务与真实 Qwen 模型验证端到端查询；协议测试覆盖分页、JSON/SSE 响应、快照变化、跨项目拒绝、凭据不进入公开响应、停用、取消/租约、错误结果与内容类型。构建后浏览器完成接入操作与窄屏验证。

不在本切片开放业务写入、自动执行第三方本地命令、旧 HTTP+SSE 传输、OAuth 动态登录、MCP task、文件/图像资源、私网连接器、第三方应用自助提交和完整工具版本生命周期。没有从现有方案中删除这些能力，后续按授权与审批闭环实施。

能力与输入/输出使用受限 JSON Schema：支持默认 2020-12 和显式 draft-07 的内联 object schema；拒绝引用、正则、format、异步校验。校验不做类型转换或填入默认值。Schema 限 16,000 字符、2,000 个节点、20 层；这是一份有明确限制的接入配置，不宣称支持所有 MCP 服务。

每次最多 10 页、100 个工具，目录最多 200,000 字符；单 HTTP 响应 256 KiB、连接累计 1 MiB；返回模型的文本/JSON 合计最多 32,000 字符。发现任务期限 60 秒、租约 20 秒、每 4 秒续租；MCP 连接总期限 45 秒，初始化和列表请求 10 秒、工具调用 15 秒。HTTP 不跟随重定向，不自动重连或重试业务调用。暂不提供生产吞吐和完整有状态服务兼容矩阵承诺。

调用前、即将发送工具请求前和接收结果后检查运行租约、取消状态、应用状态与服务状态；凭据轮换使正在使用旧绑定的调用停止返回结果。已经发出的只读请求不保证被远端终止。长期目标凭据仅经认证 Runtime 内部接口下发，不进入模型、Agent 公开快照或生成 SDK 响应。

错误以白名单原因保存并出现在流事件和运行记录中，包括 `MCP_AUTH_DENIED`、`MCP_CONTRACT_CHANGED`、`MCP_TIMEOUT`、`MCP_CONNECTION_FAILED`、`MCP_CONTENT_UNSUPPORTED`、`MCP_RESULT_INVALID`；不回传远端异常原文。

固定依赖 `@modelcontextprotocol/sdk 1.30.0`。协议依据：[MCP Tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)、[官方 TypeScript SDK v1](https://github.com/modelcontextprotocol/typescript-sdk/tree/v1.x)。平台对只读性质的维护者确认独立于远端 annotations。

## 使用入口

1. 升级运行 `pnpm db:migrate`、`pnpm build`，重新启动 `pnpm preview`。
2. 「MCP 服务」登记服务地址和独立 Bearer Token，点击发现能力。
3. 审阅工具说明及 schema，确认仅查询数据，设置平台调用名并导入。
4. 在 Agent 草稿选择导入的工具与需要的知识库，发布后创建会话。

合成服务：`pnpm fixture:mcp`，地址 `http://127.0.0.1:4201/mcp`、测试 Token `mcp-fixture-key`。仅使用合成订单 ORD-1001。当前本地项目「企业知识助手」已配置「业务订单助手」。样例服务需要单独保持运行；平台启动不自动启动测试服务。

新增六个管理 SDK 操作：`listMcpServers`、`createMcpServer`、`updateMcpServer`、`listMcpDiscoveries`、`discoverMcpTools`、`importMcpTool`。AK/SK 应用身份使用原有 `createConversation` / `createRun` 调用已发布 Agent，不能进入 MCP 管理接口。

# FlowGram 连线、面板与布局修复

2026-09-08，代码基线 `40e720176da51b36685f7a2e9e621afbb711c45d`。本轮修复用户指出的加号常显、手写节点间距和添加弹窗错位。按用户最新要求，仅以桌面端作为交付验收范围。

## 根因与实现

[固定版本主源核查](../research/flowgram-interaction-gap-2026-09-08.md)对照 FlowGram 1.0.15 官方自由布局示例与实际安装包。此前的实现虽然装入官方插件，却绕开了插件提供的状态和坐标约定。

- 连线渲染器现在依照 `hovered/selected` 决定是否渲染加号。只读、已销毁及未悬停/未选中连线不渲染按钮；保留销毁检查先于读取端口的顺序。
- 节点面板在官方 NodePanelLayer 内建立画布坐标 DOM 锚点，由 AntD 6 Popover 定位、翻转及处理边界。移除了 body fixed portal、`toFixedPos` 误用、`-60` 和固定 490 高度预测。点击条件出口采用实际事件位置，面板锚点与新节点放置坐标分离。
- 默认布局删除手写 DFS 和 380/280 步距。新建、缺少坐标的文档及 AI 候选在节点渲染后调用 `ctx.tools.autoLayout`，使用内建 Dagre 和节点实际尺寸；已有完整布局仍按保存值加载。
- 普通直线插入采用官方 `adjustNodePosition` / `subNodesAutoOffset`。新增条件节点、从条件出口添加或插入节点采用整图 Dagre。原因是浏览器复现表明，局部工具只考虑当前边，不能避免本平台条件节点多个出口与兄弟分支交叉。这个分支策略是平台适配，不冒称官方示例逐字实现。
- `fromJSON`、渲染等待和布局包含在同一 History 事务内。布局进行中阻止编辑，自动布局按钮不再重复 fit。拖动选择节点时，已打开的配置面板跟随原生单选状态。
- AI 接受候选的服务端坐标重置为 `{}`，避免复用旧定义坐标。客户端记录真实服务端 revision，测量后的布局进入未保存草稿；只有实际保存后才更新保存基线。流程设置等待文档更新成功后再关闭，避免 React 草稿与文档不一致。

## 桌面浏览器证据

使用 CUA 直接控制 Edge，没有使用 Playwright。正式控制台为 `http://127.0.0.1:5179/` 的生产构建。最后构建工作流分块 `Workflows-Cy_VAE2l.js`。

| 弹窗缩放 | 50%、100%、170% 下弹窗跟随触发点，不再因缩放偏到画布另一处。 |

| 浏览器诊断 | 独立验收页最终 error/warn 日志为空。 |

## 工程检查与边界

- `pnpm test` 22 项通过，增加了手工坐标保留与 AI 接受候选清除旧坐标的 SDK 回归断言。纯编辑测试验证图结构与布局职责分离，浏览器验证实际几何，二者不混为同一证据。
- `pnpm build`、`pnpm lint` 和 `git diff --check` 通过；修改的 AntD 组件扫描无问题。
- Standards 审查发现的异步设置提交、服务端 revision 更新顺序已修复；Spec 审查发现的虚假保存基线已修复。定点复核确认只读 AI 预览的原生布局调用链没有 readonly 拦截，但本轮没有重新生成真实模型候选做浏览器端到端验收。
- 确认没有进行中的对话、知识库、MCP 或工作流任务后重启本地预览服务，控制面和 Runtime 健康检查均通过。
- 用户已明确不需要移动端；临时小视口检查停止并恢复桌面尺寸，不宣称移动端通过。尚未建立大图性能基线，工作流分块约 849 KB（gzip 255 KB），构建保留体积警告。

本轮完成的是上述桌面编排交互修复，不代表整个平台或全部 FlowGram 最佳实践已验收。节点调试、运行可视化以及未获执行器支持的复杂节点仍遵循原有交付边界。

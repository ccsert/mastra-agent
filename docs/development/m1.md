# M1：独立 Agent 平台闭环

2026-09-07 开始转入正式工程，2026-09-08（北京时间）完成本地验收。本里程碑对应 `.scratch/agent-platform/issues/27-platform-first-slice.md`，不是整个企业平台首期验收。

## 已交付行为

1. 首次初始化组织与本地管理员，登录后创建项目。当前仅提供组织所有者模式，不包含成员邀请、完整 RBAC 或外部身份联邦。
2. 登记 OpenAI 兼容模型，凭据独立 AES-256-GCM 加密；API 响应与发布快照不含密钥。登记内置求和或有输入/输出 Schema 的 HTTP GET 工具。
3. 创建 Agent 草稿，选择模型与授权工具，按草稿修订发布。并发编辑使用修订号检查，重复发布同一配置返回同一版本。
4. 新会话固定发布版本，草稿修改和后续发布不改变已有会话。模型和工具配置当前以新增条目的方式变更，再绑定到新草稿。
5. 控制面保存任务与用户消息，独立 Runtime 通过服务凭据主动领取，Mastra 执行 Agent/工具。Runtime 仅得到当前任务的固定配置和必要凭据，不依赖数据库。
6. assistant-ui 使用官方 AI SDK 适配器，显示文本、工具参数和结果；控制面只接受本次用户输入，执行历史来自数据库。重新打开会话恢复持久消息。
7. 任务状态与有序消息流事件持久化，详情按 `after` 分页读取，支持刷新与继续加载。
8. 项目应用获得 AppID、AK、一次性展示的 SK。HMAC 绑定方法、目标路径、时间、Nonce 与正文摘要。应用不能管理资源，只能读取所属项目并使用自己的会话；撤销后新请求被拒绝。
9. Hey API 生成公开请求和类型；SDK 构建为 JavaScript 与 `.d.ts`，可以脱离 monorepo 安装。`applicationSigner` 仅负责服务端签名。

## 执行与失败语义

PostgreSQL 由控制面持有。正式预览实测控制面与 Runtime 为不同 PID，Runtime 环境中不含 `DATABASE_URL`、`POSTGRES_PASSWORD`、`ENCRYPTION_KEY`。开发启动器为 Runtime 和前端进程筛选环境变量；Runtime 从独立 `.env.runtime` 读取设置，配置路径不依赖启动目录。

任务受理后即持久化，`requestId` 在会话内幂等。同一会话同时只能有一个活动任务。用户离开页面或连接断开不会自动取消已受理任务；停止按钮向控制面请求取消，保留订阅直到服务确认，避免未收到运行 ID 时停止导致后台继续执行。

当前单 Runtime 串行执行：3 分钟任务截止、20 秒租约、4 秒续约。超时或租约失效收敛为失败，拒绝旧租约的回写，不自动重放 Agent。取消已运行任务通过续约响应传达，完成事务再次检查取消标志。此行为是 M1 的明确边界，不替代待定的客户离线续行与多节点恢复契约。

工具仅允许登记的求和或 GET JSON 接口，执行前后校验 Schema，限制调用时间和响应大小，拒绝 HTTP 重定向。此版本仅面向可信管理员配置的开发环境；GET 本身不证明业务接口无副作用，生产发布需补充工具治理和网络出口准入。

## 本地验收证据

环境：macOS、Node 24.13.0、pnpm 10.32.1、PostgreSQL 16 Docker 镜像；Mastra 1.64.0、assistant-ui React 0.15.18、AntD 6.6.3。精确依赖与镜像摘要在锁文件和 Compose 中。

- `pnpm test`：7 组通过，数据库用独立临时 schema。覆盖凭据加密/密码、HMAC/防重放、公开 HTTP+生成 SDK+Mastra 工具、多租户/项目/主体拒绝、发布和会话版本、幂等/取消/失败、租约隔离、有序事件及聊天终态竞态。
- 两个审查发现具有先失败后通过的回归：带 `$id` 工具连续执行发生编译冲突；尾部事件写入与轮询同时发生导致丢尾。分别通过任务内 Schema 编译和先读取状态再读取事件修复。
- `pnpm typecheck`、`pnpm lint`、AntD CLI 检查通过；`pnpm sdk:check` 在临时目录重新生成并比较 OpenAPI 与 SDK，无漂移。生成检查不会覆盖工程文件。
- `pnpm build` 成功。AntD 与聊天依赖包仍有大于 500 kB 的构建提示，后续应按真实页面加载与容量目标优化；未宣称完成性能验收。
- SDK tarball 安装到独立消费者目录，以普通 Node 执行，无 tsx/monorepo 源码依赖。通过 AK/SK 创建会话、执行、读取 16 个事件并取得工具结果 120；测试应用已撤销。证据 `.local/sdk-evidence.json`。
- 浏览器从界面完成初始化、项目/模型/工具登记、Agent 草稿和 v1 发布、首次对话。模型与工具确实由后台读取，页面没有模拟响应。
- 使用生产构建预览，重启后恢复同一会话的用户消息、工具结果与回复；页面将 Agent 更新发布为 v2，验证新会话为 v2、旧会话保持 v1 和历史。
- 异常路径项目通过生成 SDK 准备，浏览器实际点击发送后立即停止，运行记录显示已取消；错误模型凭据显示受控错误，运行记录为失败和 `MODEL_ERROR`。
- 桌面 1440、平板 800、手机 375 像素检查；工作台和聊天无页面横向溢出，手机可打开导航、选择页面，聊天有独立滚动区域。截图位于 `output/playwright/`。
- Runtime 从自己的 package 目录启动并读取根配置已实测；该项仅验证当前 macOS 上的 Node 启动，不能作为客户 Linux 安装验收。

本次使用 `protocol-fixture`/`slow-fixture` 等明确命名的确定性 HTTP 服务。它们验证协议、工具、隔离和状态，不证明真实模型推理、工具选择质量或业务准确率。

## 使用和后续

完整启动见根 README。三个服务统一开发启动：`pnpm dev`。验证构建产物：停止开发服务后，执行 `pnpm build`、`pnpm preview`，仍使用端口 5179/4110/4112。预览是本地验证入口，不是生产进程管理方案。

已有 `.env.runtime` 不会被 setup 覆盖；修改服务凭据后需同步控制面与 Runtime 配置。外部安装只分发 Runtime 必需设置，不能把控制面 `.env` 整体交给 Runtime。当前 Compose 仅交付数据库，应用镜像、Linux 服务安装、多节点调度、TLS、持久备份恢复与监控还需后续交付。

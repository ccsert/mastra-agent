# FlowGram 编排工作台整改

2026-09-08。基线 `f2ddca1`。本轮回应“没有按照 FlowGram 的来、体验差”的反馈，接续 [编辑器基础集成纠偏](flowgram-editor-correction.md)，将官方物料和交互模式落实到正式控制台。

## 官方依据与取舍

详见 [官方最佳实践研究](../research/flowgram-editor-best-practices-2026-09-08.md)。对照 FlowGram 1.0.15 的自由布局完整示例、节点物料、连线插入、停靠面板及变量选择源码；固定源码版本为 `ba1a9630f80263a196d31993cd85fd1c873d9ddd`。

正式控制台使用 FreeLayoutEditorProvider、DockedPanelLayer、EditorRenderer、PanelManager、WorkflowNodePanelService 和 FreeLinesPlugin。表单及历史仍由 FlowGram 维护。官方物料示例的外观适配到当前 AntD 6；没有直接装入依赖 AntD 5 的 form-antd-materials 或另一套 Semi UI。执行仍由现有平台契约编译到 Mastra。

## 用户可见的变化

- 编排进入独立全屏工作台。顶部集中保存、校验、发布和运行入口；运行按钮明确执行已发布版本。
- 添加节点使用可搜索的物料面板。连线中间和节点输出端口使用同一入口；物料可以拖到画布空白位置。节点类型限定为平台当前可执行的六类，资源缺失时禁用相关物料。
- 节点卡片展示业务资源、版本、输入引用和任务摘要，条件节点区分满足与不满足端口；节点菜单提供配置、副本与删除。
- 配置使用非模态停靠面板，点击另一个节点即可切换。AI 编排助手按需打开，避免长期压缩画布。窄屏下配置面板移到画布下方且可独立滚动。
- 变量选择按上游节点和字段组织成树，来源仍是 FlowGram Variable Engine 的可用作用域。
- 原生选择、复制粘贴、删除、撤销重做、自动布局、缩放和缩略图形成完整工具栏。复制范围是当前编辑器会话，尚未接入跨页面系统剪贴板。
- 新流程默认位置为 380 横向步距和 280 分支步距，为 280 宽度卡片及连线操作留出空间。已有保存布局按原值加载，用户可主动执行原生自动布局。
- 工具栏新增节点使用当前画布的中心位置；物料面板仍靠近点击入口，避免把工具栏的屏幕坐标误当作节点落点。

## 关键行为与修复

连线插入是一笔 History 事务：拆分指定出口的连线、插入节点、平移必要后继；在连线中插入条件节点时补齐独立的不满足结束路径。不会改变另一条分支或原始输入对象。粘贴时生成新 ID，并仅改写复制范围内的变量引用，保留外部引用及字面量。

浏览器检查发现并修复了四类实际问题：销毁旧连线后渲染器继续读取失效端口导致崩溃；PanelFactory 缓存组件返回值导致侧栏停留在旧节点；卡片点击覆盖原生 Shift 多选；AntD 6 Tabs 容器选择器不匹配导致画布没有高度。面板用 React 组件元素渲染，连线先检查 disposed，选择交由原生节点包装器处理，布局适配实际 AntD 6 DOM。

未完成的 JSON 输入保留在字段内，不写入合法定义。保存、发布、离开节点和打开 AI 面板都会检查输入有效性；未完成输入计入脏状态。响应式布局只重排现有面板，不重新挂载表单，因此不会丢失原始输入。一次编辑后无需点击“完成”才能进入草稿；保存与发布仍是明确动作。

补测拖线手势时发现：给尚未连接上游的映射节点添加后续结束节点，会在读取变量类型 `kind` 时白屏。FlowGram 的 KeyPathExpression 在此时可能还没有解析出类型。变量树现在把该状态显示为“未知”，上游缺失仍保留原有引用错误，不把它伪装成已解析的有效类型。修复后已在相同 CUA 操作路径复验。

- Standards / Spec 两条审查的问题均已处理，复核无剩余阻断。

## 明确边界

这次完成的是编排工作台和基础编辑体验整改。画布上的实时执行状态、节点级调试详情、复杂 Schema 的可视化编辑、复杂类型推断、并行/循环/子流程与相应 Mastra 适配仍待交付。

构建仍有大分块警告：工作流分块约 848 KB，gzip 约 254 KB；尚未建立大图性能和加载性能验收基线。官方演示站交互曾受其页面覆盖层干扰，不能宣称官方 Demo 全链路亲测，主要对照依据是文档及固定版本源码。

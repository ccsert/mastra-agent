## 第一轮：状态生命周期与依赖边界

- `SessionBoundary` 管理初始化、登录和退出；认证用户变化会卸载整个工作空间。
- `Workspace` 管理项目目录和当前项目；项目切换会重新建立项目界面并回到工作台，清除旧编辑器、运行详情、凭据和会话状态。
- `ProjectConsole` 内的请求属于当前项目，卸载时中止；创建会话、读取消息与事件以及编辑器提交，在异步结果返回后再次检查有效性。同项目主动刷新使用序号忽略过期结果。
- 编辑器按编辑类型与对象重新挂载，关闭后晚返回的凭据不会再次弹出。取消前端请求不意味着已经撤销服务器完成的业务写入。
- Runtime 的组合入口、Agent Worker 和公共控制客户端分别归属独立模块，HTTP 协议、租约与任务执行语义保持一致。
- `dependency-cruiser` 检查循环依赖、未解析导入、跨应用源码引用、包反向依赖应用和 Runtime 数据库依赖。显式解析 workspace exports；声明文件由 TypeScript 检查，生成 SDK 由 `sdk:check` 保证一致性。

## 第二轮：资源查询与页面职责

- `data/ProjectData.tsx` 集中定义生成 SDK 的资源查询键、取消信号、缓存和刷新策略。以 TanStack Query 代替主控制台手写的请求序号、缓存与 `setInterval`；各页面声明需要的资源。主控制台首页从 8 类首屏请求减为 5 类：模型、工具、Agent、运行、Runtime；应用、会话、知识库目录按需加载。
- 缓存实例由已认证工作空间中的项目边界持有；切项目、退出或身份变化时销毁。缓存不进入浏览器持久存储，也不使用跨用户单例。30 秒内的数据供当前项目复用，失败显式重试；缓存由项目生命周期清除，无额外 GC 定时器。
- 运行列表只在工作台与运行页面按 5 秒轮询，Runtime 状态供侧栏持续使用；隐藏窗口不继续轮询。刷新进行中复用同一请求，后台刷新失败保留上次数据并提示。手动总刷新只针对当前激活的查询，业务变更按资源定向失效。
- `QueryState` 区分首次加载、首次失败、空列表和后台失败。首次失败不显示“还没有资源”；重试只读取对应资源。Agent 编辑器自行加载模型、工具、知识库目录，目录尚未成功加载时禁止提交，避免把未加载的授权目录当成空列表保存。
- `Applications.tsx` 接管应用列表、创建抽屉、一次性凭据和撤销操作；`Runs.tsx` 接管运行列表、详情和事件分页。页面离开后临时状态释放，请求结果检查所在页面生命周期。`ProjectConsole.tsx` 从 1,197 行降至约 900 行，仍需继续拆分 Agent、会话与其他资源页面。
- `Workflows.list()` 在项目权限检查后通过一次带租户与项目条件的 JOIN 查询读取列表，共享单条读取的 DTO 映射。仍保持用户身份限定、最新草稿及已发布版本信息、100 项上限；相同创建时间以 ID 作为稳定次序。没有新增只转发 SQL 的仓储层或改变 API/SDK 契约。

实现依据：[查询取消](https://tanstack.com/query/latest/docs/framework/react/guides/query-cancellation)、[查询默认行为](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults)、[定向失效](https://tanstack.com/query/latest/docs/framework/react/guides/query-invalidation)。查询模块负责服务端状态；FlowGram Form/History 继续负责工作流草稿，不进入这个资源缓存。

## 第三轮：领域实现与功能模块

- 删除 `store.ts`，新增 `Identity`、`Projects`、`Resources`、`Agents`、`Conversations`、`Applications`、`Runtimes`。各模块持有私有依赖，保留真实 PostgreSQL 事务、租户/项目/会话权限、发布快照、幂等和任务取消语义。40 行 `Platform` 只构造领域模块并初始化数据库，不保留兼容转发方法。
- 知识库、MCP、工作流只声明各自需要的依赖；任务队列显式接收执行基础设施，不通过工作流对象访问整个 Store。新增依赖规则禁止领域模块反向引入 Platform，包含 type-only 导入。
- HTTP 入口缩至 128 行：组装认证、资源、Agent、会话/流式响应、应用接入和既有领域路由。共享响应与错误 Schema；模型地址和内置 sum 工具参数规范移到 Resources，使内部调用与 HTTP 调用遵守相同规则，不修改调用者的输入对象。生成的 OpenAPI 和 SDK 与基线逐字一致。
- `ProjectConsole.tsx` 缩至 352 行，保留导航、项目选择、工作流离开保护与编辑器打开参数。Agent 列表拥有发布/创建会话操作；工作台、会话、模型、工具和 Runtime 成为独立页面。操作所属页面关闭后，迟到响应不能重新导航或提示成功。
- 知识库分为目录、创建、文档/检索模块；MCP 分为目录、登记、能力管理；工作流分为目录、FlowGram 编辑会话、AI 编排与审阅、版本与运行列表、运行参数、运行详情、设置。`Workflows.tsx` 为 109 行，编辑会话 513 行。草稿、表单和撤销仍由 FlowGram 管理；后台查询更新不会覆盖本地草稿。
- 三类内部查询及会话历史使用项目范围的参数化查询键。详情关闭、知识库/会话选择改变时取消对应读取，后台失败保留成功数据并支持局部重试。运行详情在终态后读取最后一次节点状态；隐藏运行 tab 不轮询。
- 新增 `useOperation`：操作去重、错误反馈、请求中止与迟到回调随拥有它的页面或弹窗释放。文档删除确认随知识库详情销毁；运行弹窗关闭后不会收到迟到的完成回调。会话历史只作为 assistant-ui 的初始消息，后台刷新不重置流式消息。
- 参数化内容缓存不再采用第二轮仅根目录使用的无限 GC 时间：失去订阅后 5 分钟回收，会话历史关闭即回收；项目卸载立即取消，等子组件退订后清空缓存。StrictMode 重挂载不会被旧 cleanup 清除，没有浏览器持久化或跨项目共享实例。

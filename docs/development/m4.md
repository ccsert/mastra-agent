# M4：AI 工作流编排与执行

状态：执行闭环通过本地验收；编排编辑器仍在补齐。用户于 2026-09-08 确认推进 M4，随后指出 FlowGram 核心能力复用不足，当前整改见 [编辑器集成纠偏](./flowgram-editor-correction.md)。不改变 FlowGram 编辑、Mastra 执行的既定选型。

## 可验收行为

- 工作流作为项目资源提供列表、完整草稿修订、校验、固定发布与运行入口。平台用户管理；用户和 AK/SK 应用按入口隔离调用已发布版本。
- FlowGram 接入正式控制台，支持节点配置、连线、变量引用、保存、撤销。画布映射到一份受限语义定义，布局单独保存；错误连线不能被静默丢弃。
- AI 获取当前项目的已发布 Agent 与只读工具目录，生成或修改完整候选。候选持久保存、展示差异；接受时检查 baseRevision，不能覆盖并发编辑。生成不执行业务工具或自动发布。
- 首批节点为开始、结束、工具、Agent、变量映射和条件。条件是互斥的满足/不满足路径；M4 使用有界的分支树，每条分支独立结束，暂不开放汇合、并行、循环和子流程。后续结构继续按总方案扩展。
- Mastra 编译已校验的固定图，执行工具和已发布 Agent；Agent 可自主使用原有知识检索及工具。输入、节点输出、变量引用与最终输出独立验证，记录节点状态与输入输出。
- 发布绑定具体 Agent release 和不可变工具，不随草稿/新 Agent 发布漂移。运行期间检查租约、取消和应用/MCP 状态；故障终止，不隐式重放业务调用。
- 工作流操作进入 OpenAPI，并用 Hey API 生成 SDK。平台和独立安装的 SDK 都需完成真实模型验收。

## 首条样例

AI 根据“输入订单号，查询订单，结合知识库生成带来源采购报告”生成串行流程；随后按“订单不存在时直接返回提示”生成新候选，人工接受并发布 v2。分别验证存在与不存在的合成订单、旧 v1 仍可调用、修改草稿不改变已发布执行。

## 实施顺序

1. 语义契约、变量和图校验，固定发布及 Mastra 串行/条件执行。
2. 控制面持久化、租约与节点事件、生成 SDK；HTTP 集成与隔离反例。
3. FlowGram 正式编辑、AI 候选与冲突处理、运行详情。
4. 真实 Qwen + 订单 MCP + 知识库，独立 SDK、重启持久化、多尺寸浏览器与代码审查。

## 实现边界

FlowGram `@flowgram.ai/free-layout-editor 1.0.15` 负责画布与节点表单。平台保存一份受限 Workflow Definition 和单独布局，画布只是该定义的可编辑表示。完整草稿更新使用修订号防并发覆盖；撤销/重做历史保留于当前编辑会话，刷新后从最后保存草稿恢复。AI 原始候选、生成基线与发布快照分别持久保存。

Runtime 通过 Mastra Agent 的专用 `submit_workflow` 工具提交候选，向模型提供项目能力目录与当前定义；该工具只校验候选，没有业务执行权限。采用专用工具是为了保持平台定义、固定资源 ID 与审阅契约一致，没有依赖第二套工作流执行引擎。校验失败或原样返回会反馈模型，最多三次；平台仍要求人工审阅业务意图是否真正满足，结构校验不是业务正确性的证明。

发布时固定图、工具、Agent release 和编译适配器版本。布局与节点名称不参与执行摘要；依赖顺序也不影响版本。执行器使用真实 Mastra `.then` 和互斥 `.branch`，节点开始/完成事件由控制面在事务中校验。控制面根据已记录的上游输出计算节点输入，Runtime 独立计算并核对；两侧使用同一 JSON 规范化方式，避免 PostgreSQL JSONB 字段顺序改变模板文本。

每个项目最多 20 个待执行/运行任务，单任务期限 5 分钟、租约 20 秒、每 4 秒续租。草稿最多 24 个节点、约 100,000 字符；单值 JSON 64,000 字符。当前目录最多读取最近 100 个工具和 100 个 Agent 发布，AI 目录上下文超过 160,000 字符明确拒绝；已有固定引用的校验与发布不受目录最近条数影响。变量使用显式 literal/ref/template，不执行 JavaScript 表达式。

没有在 M4 开放并行、循环、汇合、运行中改图、任意脚本或工作流故障自动恢复。进程丢失使当前运行终止；重启后的已发布定义与历史记录保留，调用方可明确发起新任务。Agent、工具和知识检索复用已有授权与凭据能力，工作流不能绕过 MCP 停用、应用撤销或运行取消。

当前仍仅有只读业务工具；审批写入、Skills 包与隔离脚本、私网连接器、更多文档格式与可视化入库流程、嵌入 UI、统一身份中心及细粒度权限继续按原方案交付。

## 使用

升级运行 `pnpm db:migrate`、`pnpm build`，重新启动 `pnpm preview`。在「企业知识助手 → 工作流 → 订单采购报告」审阅现有流程；也可以创建空白工作流，选择编排模型、描述业务需求，等待候选后审阅差异并接受。

节点配置支持已发布资源选择和上游变量绑定，画布支持拖动与连线。保存、校验后发布固定版本；“运行”填写输入，详情中查看最终报告、各节点输入输出及未选分支。应用通过生成 SDK 的 `createWorkflowRun` 调用，协议及示例见 [SDK 文档](../../packages/sdk/README.md)。

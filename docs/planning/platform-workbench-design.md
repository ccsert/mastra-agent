# 平台工作台、运行轨迹与内置助手

日期：2026-09-09。依据当前代码与用户本轮反馈整理。本文将现有实现、这轮增量和后续设计分开；后续设计不代表能力已交付。

## 1. 当前差距

| 领域 | 已存在的实现 | 本轮增量 | 仍需交付 |
| --- | --- | --- | --- |
| Skills | 标准 ZIP 校验、不可变版本、文件读取、绑定、脚本入口授权、Docker 隔离执行 | 目录树、路径搜索、文件检查器 | 在线创建/编辑候选包、版本比较、依赖环境、私有制品位置 |
| 对话 | assistant-ui、流式输出、持久历史、固定发布版本、取消 | `/skill` 菜单、每次任务的结构化版本选择、后端校验与预加载 | 更多上下文指令、附件、分支会话、审批卡片 |
| 运行 | 有序持久事件、租约、取消、错误码 | 按步骤组织模型与工具记录、输入输出检查器、会话内运行目录、关联链接 | Runtime 原生时间、Token/费用、父子跨度、工作流统一投影、回放/分支策略 |
| 工具 | 内置求和、HTTP GET、MCP 发现/治理/绑定与真实调用 | 本轮不扩展工具执行类型 | HTTP/OpenAPI 导入、版本、测试台、业务写入审批、位置绑定 |
| Runtime | 独立进程、主动拉取任务、心跳/租约、独立构建包 | 明确展示目前只支持预配置托管身份 | 多客户注册、独立凭据、项目绑定、轻量连接器、私有正文存储 |
| Agent 编辑 | 创建/修改草稿、绑定能力、发布快照 | 分区编辑、较大的提示词编辑区、实时配置概览、步骤语义澄清 | 独立编辑路由、未保存保护、发布差异、草稿调试、评测 |
| 内置项目助手 | 暂无专属实现 | 本文确定上下文、管理工具和变更闭环 | 先创建可审阅的 Agent/Skill 草稿，再补受控系统操作 |

工具并非只有登记：它们已由 Runtime 执行。但当前 `ToolInput.kind` 只有 `sum/http_get`，MCP 通过另一条发现与导入链路进入；这与完整的工具平台仍有明显差距。Runtime 也并非内嵌在控制面：缺的是多客户接入和管理契约。

## 2. 工作台信息架构

- 项目工作台：Agents、工作流、Skills、知识库、模型与工具、会话与运行。
- 项目设置：应用接入、成员与权限、Runtime/连接器绑定、数据位置、内容与模型许可。
- 平台运营：租户、部署环境、运行健康；客户内容访问继续依赖客户授予的权限。
- 项目助手：常驻入口，带当前项目、资源路由与选定版本上下文；展开为独立会话可保留历史、轨迹、草稿和审批记录。

资源内容由具体路由驱动。目录中的筛选、详情中当前文件/轨迹记录可进入 query string；临时浮层与输入草稿不强制写入 URL。不能让组件本地状态成为资源身份的唯一来源。

## 3. Skills：包工作台

### 查看与维护

左侧目录树保留 `SKILL.md`、`scripts/`、`references/`、`assets/` 的实际层级；选择文件后右侧显示路径、大小、内容和下载入口。文本按需读取，二进制不强行解码；切换资源/文件和关闭详情取消旧请求。版本、内容摘要、可授权脚本入口在包级展示。

下一阶段使用 `SkillDraft` 保存候选文件集，编辑不会原地改写已经发布的 `SkillVersion`。提交候选时由同一套归档校验器检查路径、标准元数据、名称、编码、文件与体积限制，生成目录差异与脚本入口差异，再导入不可变版本。文件创建与 AI 生成都走这个入口。

在线编辑先支持文本，不提供浏览器中的任意 Shell。执行仍属于 Runtime 中获准版本的隔离环境。运行环境依赖和包内容版本分别固定；不能通过上传 ZIP 隐式安装宿主依赖。

### 聊天指定 Skill

`/skill` 是能力选择入口。候选来自会话固定的 Release，包含版本 ID、名称、描述、版本号和当前可用状态；不会使用最新 Agent 草稿或项目里所有可见 Skill 代替。

选择结果写入本次 `RunInput.skillVersionIds`，并进入幂等内容摘要、运行记录和用户消息 metadata。后端校验所属项目、发布快照绑定与启用状态，Runtime 再按租约与授权读取 `SKILL.md`，预加载本次选择的指令。它表达用户要求优先采用哪种工作方式，并不保证模型一定调用某个脚本，也不授予新工具或新入口权限。

其他已绑定能力仍可被 Agent 按任务需要使用。后续若提供“只允许这些能力”的限制模式，应单独表达为限制，不改变当前“指定优先使用”的语义。历史中的选中标签不自动成为下一次任务的选择。

命令提供者统一输出 ID、标题、说明、可用状态与类型化动作。后续 `/knowledge`、`/tool`、`/workflow` 要分别设计上下文引用、直接调用或启动新任务的语义，不能把它们都降为一段提示词。未实现的命令不显示为可用按钮。

## 4. 轨迹：从事件流到可检查的执行过程

研究基线是 DeepSeek 官方 [ui-trajectory](https://github.com/deepseek-ai/deepseek-harness/blob/5dda764ed3aa172535a7967b06ff95d9cbfe536a/packages/client/ui-trajectory/README.zh.md)，固定源提交 `5dda764ed3aa172535a7967b06ff95d9cbfe536a`。采用其“持久事件 → 业务投影 → 检查器”的分工，适配现有 Mastra 执行契约，不引入第二套 Agent 引擎。

### 当前增量

会话包含多次 Run；Run 中 `start-step` 建立步骤，文本分片按文本 ID 合并，工具输入和结果按 `toolCallId` 归并。并行调用不会因事件交错串在一起。检查器展示输入、输出、错误和来源事件。无完整尾部的分页不把未结束调用误判为已完成；取消或失败后未闭合的记录显示未完成。

当前事件时间是控制面接收时间，因此显示的首尾间隔明确标为接收时间跨度。模型内部推理未采集，Token/成本没有可靠字段，均不编造。运行健康与客户正文访问继续沿既有 API 的主体、项目、会话入口隔离；本轮没有向运营角色开放新的正文访问通道。

### 目标事件契约

下一阶段在聊天协议之外增加独立的执行事件信封：`eventId/runId/seq/traceId/spanId/parentSpanId/kind/phase/occurredAt/receivedAt/attempt/contentRef/usage/error`。种类涵盖 run、model、tool、skill、retrieval、workflow-node、approval、artifact。时间采集方、单位和是否估计必须明确。

模型输出流与执行遥测是两个投影，不能把所有诊断事件塞进 AI SDK 文本消息。正文通过受权限控制的内容引用读取；控制面仅获元数据的私有运行也能显示阶段、耗时和错误分类。凭据、系统内部堆栈和未经允许的工具正文不进入模型上下文或全局日志。

模型调用指标由 Runtime 记录实际请求起止、首 token、提供方 usage 和模型版本。没有定价版本时不生成费用；缓存 Token 与输入输出 Token 分别保留。工具记录实际业务身份引用、参数摘要、审批引用、目标绑定和结果裁剪状态。

### UI 与恢复

目标为会话/Run/步骤/调用的层级列表，加真实时间跨度概览；支持按错误、工具、节点、耗时筛选和检查器深链接。长历史采用游标分页和虚拟列表，检查旧记录时停止自动跟随。工作流节点使用同一检查器，节点内 Agent 步骤作为子级。

轨迹浏览是只读回放，不会再次执行业务工具。重新执行、从检查点继续、创建分支分别创建可审计的执行意图，先依据写入幂等和恢复策略判定可用性。当前不提供虚假的“重放并恢复”按钮。

## 5. 工具平台：能力契约与执行绑定

沿用 [工具与 MCP 治理方案](tool-mcp-governance-proposal.md)，拆出以下对象，而非继续往一张工具登记表追加可变字段：

| 对象 | 关键内容 | 服务边界 |
| --- | --- | --- |
| ToolService | 来源应用、项目、协议、责任人 | 登记与发现 |
| ToolVersion | 输入输出 schema、动作类型、说明、摘要、不可变版本 | 发布与引用 |
| ToolBinding | 版本、目标环境、Runtime/连接器、凭据引用、网络目的地 | 执行位置与身份 |
| ToolGrant | 应用/用户/Agent 范围、动作、业务对象约束 | 授权判定 |
| ToolInvocation | 参数摘要、幂等键、审批、尝试、结果与轨迹 | 执行和审计 |

HTTP/OpenAPI 接入顺序：上传/引用规范 → 选择 operationId → 检查入参和返回 schema → 配置认证引用和目标绑定 → 用合成输入验证 → 保存候选版本 → 发布并授权。支持路径、query、header、body 的类型化映射，模型不得任意指定目标地址或认证 header。

MCP 接入保留远程发现分页、能力变化检测和快照；新增版本差异、绑定健康与测试记录。服务自报 annotations 是线索，不是自动审批结论。需要 stdio 的服务在客户 Runtime 的受管进程中启动，控制面不执行登记内容中的任意命令。

业务写入默认要求动作确认；审批卡展示目标、参数摘要、业务身份、影响范围和有效期。客户按版本/动作/业务对象预授权后才自动执行。批准与实际参数摘要绑定，参数变化必须重新判定；模型文本“用户同意了”不是批准凭证。调用前复验授权，超时后结果未知不直接重试非幂等写入。

## 6. Runtime 与轻量连接器接入

当前 `Runtimes.list`、队列 claim 与内部认证绑定单个配置身份。不能只增加一个注册表单就宣称完成多 Runtime。沿用 [部署方案](runtime-deployment-profiles.md)，先交付下面的后端链路：

1. 管理员在项目/环境创建有到期时间、限一次使用的 enrollment token，指定租户、目标环境、组件角色和允许能力。
2. Docker 或 Linux 安装向导在客户侧发起兑换，生成独立设备身份；长期凭据留在客户配置文件/Secret，控制面只保存验证材料与吊销状态。
3. 组件主动维护连接，报告 Runtime/适配器/沙箱版本、能力就绪情况、队列容量和健康。心跳在线、可接任务、单项能力就绪分别展示。
4. 项目显式绑定环境，调度只从该项目授权且满足所需能力的位置选择执行者；领取、续租、内容读取和结果回传都以认证得到的 Runtime principal 校验，不能信任请求头自报 ID。
5. 停用先 drain：停止新任务、处理已有租约；凭据轮换有受限重叠期；吊销立即阻止新连接与新租约。安装包、升级、回滚与健康检查均对应固定版本。

轻量连接器仅承接登记好的工具/MCP/检索调用，不能变成私网任意 HTTP 代理；完整 Runtime 另承接 Mastra Agent、工作流、文档处理和 Skill。Agent 主执行位置与工具/知识位置可不同，跨位置结果必须经过内容和模型服务许可。

私有执行要配套客户侧内容存储和本地授权解析；现有“正文经过集中 API”的托管路径不能直接充当私有数据驻留实现。平台托管数据和私有数据均遵守用户已确认的内容许可、运营人员访问与撤销/删除分离政策。

验收至少包含：两个租户三个 Runtime、伪造 ID、跨项目领取、轮换与吊销、断线取消、旧租约结果、Docker 重启、Linux 服务重启、不可用沙箱、平台 Agent 经连接器调用合成私网工具。未经这些验证不标记多客户运行可用。

## 7. Agent 编辑的目标形态

目标路由 `/projects/:projectId/agents/:agentId/edit`，另设 `/agents/new`。编辑资源 ID、修订和查看的发布版本由路由确定。与本轮加宽分区编辑器相比，下一阶段应提供以下完整流程：

| 区域 | 编辑内容 | 用户得到的反馈 |
| --- | --- | --- |
| 基本信息 | 名称、用途、负责人/标签 | 项目可发现性与责任 |
| 指令 | 角色、任务步骤、输出格式、约束、变量 | 校验、变量来源、提示词预览与版本差异 |
| 模型 | 模型服务、参数、输出格式、预算 | 所选服务能力、许可与预计限制 |
| 能力 | 固定工具版本、知识库、Skill 版本/入口 | 每项用途、实际权限、不可用原因 |
| 执行 | 默认位置、能力依赖、超时/步骤预算 | 可执行环境与就绪检查 |
| 调试 | 合成输入、草稿快照、参数与结果 | 引用同一轨迹检查器，标注草稿与环境 |
| 发布 | 草稿修订、与当前版本的差异、校验结果 | 明确发布内容和受影响的新会话 |

使用 revision 乐观并发控制，冲突显示服务端新修订并允许比较，不能覆盖他人修改。跨路由、关闭与刷新保护未保存内容；草稿调试不污染生产会话，且不能绕过真实工具审批。未实现的控制项不要以可编辑表单出现。

先补 Agent 独立编辑路由、未保存保护和版本差异；随后接入草稿调试、评测样例和上述工具/Runtime 绑定。能力模型稳定后再加入更细的模型参数与预算，而不是先写一排无后端语义的输入框。

## 8. 内置项目助手

目标：用户说“创建一个依据采购制度查询订单并输出报告的 Agent”，助手读取当前项目实际能力，提出可执行配置，生成 Agent 草稿与需要的标准 Skill 候选包，展示差异和缺失依赖，获准后应用；用户再决定发布和执行业务动作。

### 如何理解项目

- 平台能力说明由版本化的产品指南和契约目录提供；源码仓库全文不自动发给模型。
- 当前项目资源通过按需只读工具查询，包括模型、工具版本、知识库状态、Skill 元数据、Agent/工作流发布关系、Runtime 可用性。
- 用户当前选中的资源、版本和草稿作为明确上下文引用；正文仍走内容许可，不把 URL 或页面可见当作额外授权。
- 诊断通过获准的运行轨迹与错误分类获取事实，无法读取的内容明确说明，不编造系统状态。

### 管理工具集

| 工具 | 输出/效果 | 权限与确认 |
| --- | --- | --- |
| project.describe / resources.search | 项目事实、可用能力、版本引用 | 当前用户可读范围 |
| agent.propose / agent.diff | 类型化草稿、依赖缺口、与 baseRevision 的差异 | 不写已发布对象 |
| skill.propose / skill.validate | 标准文件树、校验报告、脚本入口差异 | 候选存储独立于发布包 |
| change.apply | 将确认的变更集写为 Agent 草稿/Skill 新版本 | 精确变更摘要、目标修订、幂等键；应用前复验 |
| run.inspect | 合规范围内的轨迹与诊断 | 正文权限、来源位置许可 |
| agent.publish / workflow.publish | 发布已经检查的明确版本 | 有发布权限且确认对应变更 |
| business.invoke | 普通业务工具调用 | 完整复用工具审批、对象范围、实际业务身份 |

首个实施单元只需要项目发现、Agent 草稿提案、标准 Skill 候选包和确认应用，闭环后再扩展发布、工作流变更与业务操作。助手不是拥有平台超级管理员凭据的普通 HTTP 工具。

### 后端边界与变更对象

新增 `assistance` 模块负责会话绑定、上下文组装、工具注册和变更集；通过 `Agents`、`Skills`、`Workflows` 的公共接口应用命令，不直接修改其他模块的数据表。Runtime 用短期、按运行及主体限制的管理能力调用控制面，跨网络使用生成 SDK，不给模型长期 Session、AK/SK 或数据库凭据。

`ChangeSet` 至少记录主体、项目、请求、目标资源、baseRevision、候选内容引用、规范化差异、摘要、所需权限、到期时间、状态及应用结果。状态为 proposed → validated → approved → applied/rejected/expired/conflicted。批准发生在用户界面，绑定具体摘要；审批后发生资源变化则进入 conflicted。多资源应用使用事务或可见的分步结果，不能把部分成功标记成完整成功。

生成与应用分开：模型输出先经过类型、引用、标准包和授权校验；未知字段、不存在资源、超范围脚本、伪造审批被拒绝。标准包的 `allowed-tools` 不能提升权限。助手的操作轨迹与创建出的资源相互链接，SDK/嵌入组件/iframe 后续复用同一审批与轨迹契约。

## 9. 实施顺序与完成条件

1. 本轮：Skills 文件树、指令调用链、运行投影和会话关联、Agent 编辑器分区。验证 UI、权限/幂等、固定版本、撤销和 Runtime 实际预加载。
2. Agent 工作台：独立编辑路由、草稿保护、发布差异和隔离调试；以刷新还原、并发冲突和草稿不影响旧会话验收。
3. 工具生命周期 + Runtime 接入：先固定版本/绑定/身份契约，再做登记、健康和测试台；以私有合成工具和跨租户拒绝验收。
4. 内置助手第一条闭环：发现项目 → 生成 Agent/Skill → 校验 → 用户检查差异 → 应用草稿 → 发布后真实对话；对资源冲突、权限撤销和恶意包内容做反向验证。
5. 统一事件信封和内容引用：补 Runtime 时间/usage、父子跨度、工作流与私有运行投影；随后做可视化时间概览、虚拟列表和受限制的恢复。

各阶段都以可用业务路径验收，不能用目录重排、UI 占位或设计文档代替完整链路。

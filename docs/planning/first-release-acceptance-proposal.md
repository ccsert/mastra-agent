# 首期验收闭环与验证规模方案

日期：2026-09-07。对应[首期验收决策](../../.scratch/agent-platform/issues/04-first-release-acceptance.md)。用户已选择“先采用通用合成样例，容量先实测，之后补客户目标”。下文闭环成为首期验收基线；具体合成数据量和负载阶梯是可调整的工程输入，不是客户真实业务或性能承诺。

## 首期要证明的结果

业务团队可以在平台登记能力、获得资源授权、发布版本，并在平台界面或自己的业务系统中调用。业务系统接入后复用同一套运行、知识库和审计语义；客户私有工具与知识库能按授权参与平台托管 Agent 的任务。

验收分别保留独立 Agent、独立知识库和工作流三条路径。一个组合演示不能替代三项能力各自可用，且“接口返回成功”不能替代权限、版本和失败行为正确。

## 已采用的合成场景

样例名称为“业务文档与订单助手”。它是用于验证平台的通用夹具，后续可以替换为任何客户业务，不把平台产品限定在订单领域。

| 项目 | 合成夹具建议 | 用来检验什么 |
| --- | --- | --- |
| 客户与角色 | 两个租户；各有业务使用者、项目维护者；另有平台运营 | 租户隔离、管理与正文权限分离 |
| 项目与入口 | 每租户一个项目、test/prod 两环境；订单应用、客服应用和平台入口 | 环境授权、应用任务、用户委托及默认会话隔离 |
| 运行位置 | 一个托管 Runtime、一个私有 Runtime；轻量连接器单独运行一次相同私网工具用例 | 托管/私有/混合路由，完整 Runtime 与连接器职责 |
| 文档 | 产品手册、业务规则、带区域 ACL 的订单说明；包含旧版、修订版、删除项和错误文件 | 入库、版本更新、权限过滤、失败定位及引用 |
| 查询工具 | `query_orders`，数据按用户允许区域过滤 | 工具实际身份、输入输出 schema、模型上下文范围 |
| 写入工具 | `create_followup_task`，只写合成业务库，能查询执行结果并识别业务幂等键 | 人工批准、重复投递、超时后结果不确定 |
| Skill | 标准目录打包 ZIP；Node/Python/Bash 报表入口，依赖预先准备 | 上传兼容性、固定版本授权与脚本执行 |
| 模型 | 使用客户明确许可的模型服务；工程阶段可使用确定性替身测试传输和恢复 | 真实生成质量与协议正确性分开验收，替身不算 AI 质量通过 |

私网环境是独立的逻辑与网络边界。两个本地容器仅可用于早期协议实验，不能代替真实客户私网、防火墙、代理和断网条件。

## 三条必须独立跑通的链路

### 独立 Agent

在平台创建 Agent，绑定授权的知识库、工具及 Skill 版本，直接发布使用；不要求先创建工作流。业务人员提出“按允许区域汇总订单，结合规则生成处理建议和报表”。Agent 可在授权范围内选工具和执行固定脚本。脚本依赖已准备、版本与范围已授权时无需再逐条人工批准；业务写入是否需要批准由工具动作政策决定。

完成后能够恢复历史、查看获准引用和下载自己的产物。共享同一 Agent 的另一个应用或用户不能只凭会话 ID 读取该历史。平台运营能定位失败步骤；未获客户内容权限时看不到正文。

### 独立知识库与文档工作流

用户先创建知识库并指定存储/检索位置，导入文档后能独立进行检索调试。AI 根据“解析、按业务元数据分块、校验、入库”的意图生成完整流程，FlowGram 显示节点和连线，用户可用自然语言修改并审查变更；验证通过后发布，由 Mastra 按版本执行。

文档更新、删除及 ACL 改变必须影响后续检索。失败文件可以定位并重试；重试不能重复增加同一批数据。引用能回到获准的文档版本。修改流程草稿不会改变已开始的入库任务。分块、embedding、索引提交与删除的具体事务边界由知识库生命周期契约决定，不在本方案假定框架自动提供。

### 平台与业务系统接入

同一发布 Agent 通过平台聊天、OpenAPI、生成的 SDK、React UI 组件和 iframe 使用，输入、权限、运行状态、暂停/恢复与错误语义一致。React 与 iframe 不持有长期 SK；应用服务任务与可信用户委托分别展示审计上下文。

在混合模式中，会话和 Agent 在平台，知识库与查询工具在客户私网。客户组件主动连接平台，平台经授权调用私有资源；仅允许的片段/字段返回，并仅进入许可模型。撤销内容传输后，新请求按策略被拒绝；已保存副本是否删除必须单独记录，不能伪装成“撤销即远程擦除”。

## 验收场景矩阵

以下是应达到的行为，不表示当前平台功能已存在。

| 场景 | 可观察的通过条件 | 必须保留的证据 |
| --- | --- | --- |
| 自然语言编排 | 模型生成并修改可解析的完整定义；编辑器往返不丢执行语义；无授权资源不能发布 | 输入、生成定义、差异、校验结果、发布摘要与运行输出 |
| 工作流版本 | v1 运行中发布 v2，旧运行仍按 v1；重启恢复不切换定义 | 发布记录、run 绑定、重启前后事件 |
| 独立 Agent | 无工作流也可聊天、调用授权工具与 Skill，并返回引用及产物 | Agent 配置、工具清单、调用与产物记录 |
| 独立知识库 | 可单独导入和检索；新旧文档、删除和 ACL 更新结果正确 | 文档状态、版本、检索结果和拒绝案例 |
| 认证两模式 | 统一登录、应用自身任务和可信用户委托均可调用；伪造用户、错租户/环境拒绝 | 脱敏协议请求、claims、授权决定与主体审计 |
| 工具注册 | 外部应用注册后经验证与授权才能调用；schema 改变不静默覆盖发布绑定 | 发现快照、校验、授权、兼容性结果 |
| 写入审批 | 批准绑定具体动作与参数；修改参数需重新判断；重复恢复不重复业务写入 | 批准记录、幂等键、业务结果查询 |
| Skill 导入与执行 | 正常 ZIP 可导入；危险归档拒绝；格式合法但依赖缺失显示兼容问题 | 包摘要、导入判定、环境版本、实际执行与拒绝结果 |
| 使用入口 | API/生成 SDK/React/iframe 与平台使用同一权限和状态语义 | 真实协议客户端与浏览器证据，不只组件截图 |
| 混合数据位置 | 私有资源默认不出域；显式许可后只返回许可内容，禁用模型服务拒绝 | 出入口事件、内容分类、许可版本、边界抓取的合成 canary 检查 |
| 网络与故障 | 私网无业务入站要求；断连、重连、超时、取消均有明确定义的状态 | 网络路径、连接日志、投递关联及恢复后业务核对 |
| 会话与正文 | 默认隔离；显式共享区分查看/继续/附件；运营未授权仅状态可见 | 不同主体的正反例和访问记录 |

目前已取得 Skill 基础隔离与 Mastra 适配的[18 组实验](../research/skill-sandbox-prototype-2026-09-07.md)，以及工作流跨进程持久化的[24 进程、10 项检查](../research/workflow-persistence-probe-2026-09-07.md)。后者验证了 SDK 行为，尚未证明平台完整接管与发布协议。ZIP 导入、AI 编排、完整聊天、SDK/iframe、身份服务和客户连接器均未因此通过。

## 规模与指标如何落地

先建立可重复的工程负载，再用客户目标定正式验收阈值。

| 层次 | 建议范围 | 如何解释结果 |
| --- | --- | --- |
| 本地正确性 | 两租户、两业务入口、test/prod 两环境；少量固定文档；2 个并发调用用于污染检查 | 覆盖边界和状态，不输出容量结论 |
| 集成负载探索 | 从 1、5、10 个并发逐档增加；普通聊天、检索、入库、长脚本分别记录 | 这些是实验输入；按资源预算停止，不是首期并发承诺 |
| 客户目标验收 | 客户/Runtime 数、用户/应用数、并发及队列、文档数/大小/格式、更新速率、最长任务时长 | 需要用户业务目标与目标机器；在选定条件下给出阈值和失败标准 |

应记录网关鉴权耗时、排队时间、模型首 token 与总时长、检索/重排耗时、工具往返、入库吞吐、沙箱准备/运行时间、恢复时间及失败比例。基础设施耗时和外部模型/业务系统耗时分别呈现。平均值不代替 p95/p99；样本不足时明确标注，不生成失真的尾延迟指标。

暂不填任意的“99.9% 可用性”“百并发”或保留天数。真实业务文件、目标 Linux 发行版/架构、CPU/内存/存储，以及外部模型配额仍待补齐。缺少这些信息不妨碍契约和小规模原型，但会阻止正式容量与交付承诺。

## 可继续推进的顺序

工具/MCP 基线及工作流持久化事实已经明确，目前收敛[恢复契约](runtime-recovery-contract-proposal.md)、[发布与版本方案](publication-and-version-pinning-proposal.md)及 AI 编排边界；身份中心和内容保留模板作为相关问题继续讨论。具备相应前提后分别做 FlowGram→Mastra、完整持久恢复和 assistant-ui 接入原型，最后串联本方案的三条链路。

用户已采用通用样例并选择容量先实测，验收基线票据已关闭。后续原型据此继续；之后仍需在客户目标环境补齐真实业务、容量和交付验收，不能把合成结果直接当作生产承诺。

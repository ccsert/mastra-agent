# Runtime 断网、挂起与故障恢复契约草案

日期：2026-09-07。对应[Runtime 故障恢复决策](../../.scratch/agent-platform/issues/07-runtime-failure-contract.md)。状态：**待讨论的产品契约，尚未实施**。既有内容许可、写入默认确认、Skill 按版本与范围自主执行保持有效；本方案集中确定失联和故障时的行为。

依据：[24 进程持久化实验](../research/workflow-persistence-probe-2026-09-07.md)及[固定源码核查](../research/mastra-persistence-source-2026-09-07.md)。基本挂起恢复、同 ID 版本漂移与写入崩溃窗口已实测；网络、租约、审批协议和自动接管没有因此通过验收。

## 建议首期采用的边界

1. 客户 Runtime 与控制面断开时，**已接收任务在尚有效的许可内继续可达的本地执行**；不新增任务，不扩大权限，到期停止发起受影响操作并请求暂停。需要私网之外的资源而无法到达时，只等待受影响的依赖，不把断网误报为业务失败。
2. **先交付同一 Runtime 执行归属内的进程故障恢复**：持久化状态可用，确认旧执行者退出或已被可靠隔离后，新执行者恢复。跨主机迁移通过受控交接；首期是否要求跨主机自动接管，由本轮产品选择确定。
3. 外部写入超时或崩溃后结果不明时，先使用同一业务意图键核对或幂等重试；没有可靠能力时等待人工核对。控制面连接恢复不会自动重发所有写入。
4. 新运行与旧运行分别绑定版本。部署新版本不修改已有运行；恢复需要的制品与内容应仍可用且仍获准使用，缺失时明确阻断，不能改用 latest。

第一、二项是本轮待选择的取舍。第三、四项是将已确定的工具治理和固定版本要求落实到故障场景，不再重新征求这些方向。具体保留模板与数值仍由[内容策略](content-policy-lifecycle-proposal.md)承接。

## 三种失联要分开

| 失联范围 | 仍能做什么 | 不应推导什么 |
| --- | --- | --- |
| Runtime 仅与控制面失联 | 已接收任务可按选定离线政策使用仍可达的本地模型、知识库和业务工具 | 不代表所有模型/工具都断网，也不代表获得新的离线使用权 |
| 平台 Runtime 与客户连接器失联 | 平台仍能处理自己的其他任务；受影响的私网调用等待连接或核对结果 | 不能在平台自动复制私有资源或把写超时当未执行 |
| 执行者与自己的状态存储/授权执行服务失联 | 阻止新的受影响操作并请求停止，等待恢复或处置 | 不能只凭内存中的 owner 或旧许可继续产生副作用 |

轻量连接器只承接已分派的受限调用与回执，不因断网自动变成可以独立编排新 Agent 任务的 Runtime。

## 控制面与运行侧各自保存的事实

控制面管理发布期望、资源授权和客户政策；实际运行所在的 Runtime 保存执行归属、检查点、动作账本及完整运行结果。控制面的状态视图是许可范围内的投影，应展示最后同步时间；失去心跳显示“状态待同步”，不能自行判定运行失败或已经停止。

任务接收分两层：接入服务可能已经持久化排队请求，但只有运行侧持久化运行记录、不可变发布绑定和必要输入后，才算 Runtime 已接收。前一层显示等待分派；后一层可以依据恢复契约继续。请求重试沿用同一接收标识，参数变化产生冲突或新任务，不重复创建同一意图的运行。准确协议由 API 规格定义。

完整检查点含业务正文，应在获准位置保存。控制面可以接收被许可的状态、引用、计数和摘要字段；不能为故障恢复默认上收全部输入、工具结果或 Skill 内容。

## 离线许可与执行归属不是同一个期限

| 控制项 | 解决的问题 | 到期或失效后的行为 |
| --- | --- | --- |
| 运行授权有效期 | 哪个主体可在何环境使用哪些资源/动作/内容/模型 | 不再发起依赖该许可的调用；进行中的处理请求停止 |
| 执行归属有效性 | 哪个执行者此刻能继续某次运行 | 旧执行者不得继续领取步骤或放行业务动作；新执行者先完成归属检查 |
| 动作批准有效期与挂起代次 | 哪一次具体业务意图已由谁批准 | 过期、参数或代次不匹配不能用于恢复动作 |
| 内容/检查点保留期限 | 哪些恢复材料仍可合法保存和使用 | 删除或不可用可能使运行失去恢复条件，不能靠执行租约延长内容许可 |

以上期限不能直接复用一个登录 token 的 TTL。授权凭据需绑定主体、项目环境、运行/资源范围、发布引用、政策修订与允许用途；具体签发格式和传输不在本草案提前定为公开 API。

若采用“有效许可内继续”，最长离线续行取相关许可中的最早截止时间；失联不会重置倒计时。没有离线有效性的许可必须在线检查；撤销已到达执行方时立即拒绝新操作，不能等凭据自然过期。离线期间无法获知的撤销仅能在重连同步或许可到期时发现，不能承诺即时生效。

为验证逻辑，原型可以采用 30 秒许可和短周期检查作为**测试参数**；正式默认值、客户可配置上下限、时钟偏差与重启后校时规则另行测量和确定。时间不可信或无法证明许可仍有效时不扩大执行权。这里不设置未经确认的生产秒级承诺。

授权检查覆盖 Agent 每次模型/工具调用、Skill 的业务工具入口、知识库处理服务、内容出域和结果回传。只在工作流起点检查一次，无法兑现长任务中的撤销与到期规则。

许可失效时区分“禁止新增操作”“已请求停止”“已确认停止”。对外请求已经发出或脚本正在运行时，应请求取消并阻断后续受控出口；无法确认终止的动作继续显示待核对。已发送的字节和已完成的业务写入不能被取消撤回。

## 断网与重连矩阵

| 场景 | 建议行为 | 需要的观测 |
| --- | --- | --- |
| 本地订单报表已接收，控制面断开，许可有效 | 使用已固定版本和仍可达的获准资源继续 | 本地事件与制品摘要，控制面显示状态可能滞后 |
| 断开期间，本地业务系统提交新任务 | 首期默认不接收，返回可识别的暂不可用原因 | 未创建实际运行；重试不重复受理 |
| 新任务已在接入端排队，但 Runtime 尚未接收 | 保持等待分派，受队列期限和输入保存许可约束 | 不能显示成 Runtime 已执行 |
| 平台任务等待客户私网查询，尚未发送 | 等待连接，可按只读查询规则重试 | 分清未发送与已发送 |
| 私网写入已发送、响应丢失 | 标记动作结果不确定，先查业务账本或幂等结果 | 业务意图键、参数摘要、发送记录和后续核对 |
| 已收到正文但断网后保存许可到期 | 停止新增使用并按生命周期处理，不能为重传无限缓存 | 正文与元数据队列分开；删除及可恢复性分别显示 |
| 审批等待中断网 | 保持待批准；批准入口不可达时不伪造批准 | 挂起代次、批准有效性、最后同步时间 |
| 许可到期时正在生成/执行脚本 | 请求取消，阻断后续模型/工具/内容出口 | 取消请求、执行退出或无法确认状态分别记录 |
| 连接恢复 | 先核对身份/政策修订及执行归属，再处理待办与许可回传 | 旧许可不因重连自动重新生效 |

重连补传应按运行事件序号去重；命令、批准和业务动作各自保留独立标识。回传正文前重新检查当前目的地与保存许可，不能仅依据离线前一次传输批准。队列、缓存和回执需要容量上限，超限采用背压或暂停，不无限占用客户磁盘。

## 故障接管和不确定动作

正常挂起走 Mastra 的 resume；活跃进程崩溃后的恢复走适用的 restart 路径，两者的 SDK 状态规则见研究报告。平台在它们之外统一检查当前执行归属，不能把 resume 的状态竞争保护推广到全部 restart 场景。

建议首期由运行侧的持久化协调组件串行决定归属，控制面只发请求。恢复必须证明旧执行者退出，或其业务调用权限已被可靠隔离；只观察“租约看起来过期”或“收不到心跳”不足以排除旧进程继续写入。跨主机自动接管若纳入首期，还须验证旧执行者失联、存储故障、网络分区和下游拒绝过期执行代次的完整路径。

工具调用至少区分：未发出、已发出等待结果、结果已确认、结果不确定。发送记录在副作用之前持久化，回执与可恢复结果随后持久化；发出记录存在但无确认时按不确定处理。幂等键绑定同一业务意图与参数摘要，恢复沿用原键；循环/子流程/批量动作必须有各自的意图标识，不能只使用 run ID。

重试允许范围由工具能力决定：可核对则先查；实际支持幂等则按原意图重试；两者都不支持则人工核对。即使旧步骤在 Mastra 中显示 running，也不能据此判断业务系统尚未完成。人工标记未执行或已执行需记录依据，不能作为绕过审批的新写入入口。

取消运行也采用同一核对过程。界面可以先显示取消已请求；仍有不确定外部动作时，不得显示所有业务动作已取消。重新执行已终止任务需创建新的运行，并重新判断授权和业务意图，不能把原成功任务的 restart 当作“再跑一次”。

## 运行恢复所需的版本材料

旧任务的发布版本、工具/Agent/Skill/子流程实现和 Runtime 兼容环境必须能够重新装配。新发布只改变后续新任务入口；已接收、挂起及正在核对外部结果的任务继续引用原材料。引用被主动撤销或制品缺失时显示阻断，不能自动换用新版本。

旧制品保留与业务正文保留分开：制品存在不意味着旧数据仍能读取；保留旧任务也不意味着可以突破内容删除规则。正式发布票将确定回滚窗口、升级迁移和清理流程；本票只列出恢复的必要条件。

## 如何验收，哪些数字尚不承诺

| 验收输入 | 必须观察到 |
| --- | --- |
| 控制面断开但本地依赖正常；随后许可到期 | 有效期内按所选模式处理；到期后没有新的受影响调用 |
| 正文 canary 进入快照、错误、队列和回执 | 未许可内容不进入集中管理投影；补传重新鉴权 |
| 旧进程存活但心跳丢失 | 不发生未经归属检查的双重执行，或下游拒绝旧代次 |
| 写入前、写入后、检查点前分别杀进程 | 状态与效果可核对，结果不确定时不盲目重试 |
| 同一挂起代次重复批准；随后再次挂起 | 旧批准不能消费新一轮挂起或变更后的参数 |
| 发布 v2 后恢复 v1；再删除 v1 的必要制品/内容 | 先按 v1 恢复；材料缺失后明确阻断而不漂移 |
| 重连时旧政策已撤销，旧事件与命令重复投递 | 撤销先于继续使用，状态事件去重，业务意图不重复创建 |

分别测量故障发现、旧执行者停止确认、依赖装配、检查点读取、继续执行的耗时，以完整恢复业务所需时间评估 RTO。核对最近可恢复的数据时间点与已确认受理记录，评估可能丢失的数据时间窗口及 RPO；额外记录任务丢失数量和实际业务效果，不能把这些计数直接当作 RPO。进程重启、存储损坏、整机损坏是不同故障模型，不能用本地杀进程成功声称零丢失或跨主机高可用。

保留天数、最长挂起时间、队列期限、授权最大离线时间、自动恢复时限及备份策略尚待配置与目标环境证据。可采用短测试参数验证状态转移，不能把它们发布为生产 SLA。

## 本轮需要选择的两项

- 控制面失联：建议已接收任务在有效许可内继续本地执行，到期暂停；新任务不受理。替代方案是失联即暂停，或首期就支持离线受理新任务与更完整自治。
- 恢复范围：建议先验证同一 Runtime 执行归属内的进程自动恢复和受控迁移；跨主机自动接管是否必须进入首期，由业务连续性要求决定。

在这两项答复前，本文保持草案；数据与版本原则可继续用于设计，不能把建议默认值记录为用户已选。

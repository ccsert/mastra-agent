# Mastra 为执行核心时的编辑器选型

日期：2026-09-07。状态：用户已选择 FlowGram 前端编排与 Mastra 执行；局部文档往返已有实测，完整表单、变量与 AI 原型待验证。本文保留比较依据，最终边界见 [ADR](../adr/0001-flowgram-authoring-mastra-execution.md)。

## 建议

按当前完整平台范围，优先验证 Mastra + FlowGram 前端编辑框架。FlowGram 的表单、变量作用域和历史记录能力可以减少自建工作流编辑基础设施的工作。若产品最终只需要 AI 生成流程后展示、修改少量参数，React Flow 更可能是总体成本较低的选择。

这是根据功能边界作出的工程判断，没有工期、性能或兼容性实测依据。没有安装依赖或运行原型。

## 官方能力与代价

| 维度 | FlowGram 前端 | 原生 React Flow |
| --- | --- | --- |
| 初次接入 | 需理解表单、变量、文档及插件等框架概念 | 节点和边的 React 接入更直接 |
| 节点配置 | 有表单引擎，可复用校验、联动等机制 | 配合 Ant Design 构建，并自行组织数据与校验 |
| 变量系统 | 提供作用域链与类型相关能力；需要与 Mastra 可访问范围对齐 | 上游变量检索、嵌套作用域和引用失效处理由平台实现 |
| 控制结构 | 支持固定/自由布局及复合节点；需限制为 Mastra 能表达的结构 | 自行设计分支、并行和循环的编辑交互与合法性约束 |
| 编辑历史 | 有历史记录等工作流编辑配套能力 | 可参考官方示例；业务级修改事务仍需自行组织 |
| 布局 | 提供布局相关能力与插件 | 官方推荐接入外部布局库，如 Dagre、ELK |
| Mastra 对接 | 仍需维护模型适配和执行事件映射 | 同样需要映射；可以直接围绕 Mastra 执行定义设计编辑模型 |
| 自定义空间 | 接受框架约定，部分能力可选用 | 较少工作流约定，也承担更多自主维护责任 |

FlowGram 官方明确提供画布、节点表单、变量作用域和物料，同时记录固定/自由布局、历史记录等能力：[简介](https://flowgram.ai/guide/getting-started/introduction)、[节点表单](https://flowgram.ai/guide/form/form)、[作用域链](https://flowgram.ai/guide/variable/custom-scope-chain)。表单渲染与现有组件库的连接需要原型验证；不能把示例视觉组件当成必须绑定的 UI 技术栈。

React Flow 的核心文档覆盖自定义节点、连接、状态管理和子流程；自动布局依赖外部库：[核心文档](https://reactflow.dev/learn)、[布局说明](https://reactflow.dev/learn/layouting/layouting)。它也有官方 Workflow/AI Workflow Editor Pro 模板，但当前模板采用 Next.js、shadcn/ui、Zustand，仍需改造才能符合本项目 Vite + Ant Design 的候选技术栈：[Workflow Editor](https://reactflow.dev/ui/templates/workflow-editor)、[AI Workflow Editor](https://reactflow.dev/ui/templates/ai-workflow-editor)。

## 复杂度主要来自哪里

完整平台的复杂度高。客户私网连接、运行恢复、身份与工具授权、知识库文档生命周期是主要工作；编辑器框架只能减少其中的前端工作。

编辑器内部，最耗费精力的是保持执行含义与编辑行为一致：删除上游节点后引用如何处理、循环内部变量能否被外部引用、并行分支如何汇合，以及 AI 修改多个节点能否作为一次可撤销操作。

AI 生成完整定义只是起点。AI 和人工应通过同一套定义修改与校验路径写入；采用稳定节点标识和草稿版本，检测过期修改，并保留不受本次修改影响的参数和布局。

Mastra 动态图采用有序和嵌套控制结构。例如 conditional 的含义是并行执行所有条件为真的分支，不能直接假定为仅选择第一个匹配分支。编辑器的变量作用域与控制结构都应以实际执行定义为准：[Mastra 动态定义](https://mastra.ai/reference/workflows/dynamic-workflow-definition)。

## 控制复杂度的边界

- 平台流程文档保存版本、授权引用、执行定义和独立布局信息；执行语义优先复用 Mastra，避免维护两套各自演进的执行含义。
- 编辑器的数据结构是编辑视图和交互状态；发布输入来自经过校验的流程定义。
- AI 修改受约束的定义或编辑操作，通过同一校验路径更新画布；发布校验在服务端执行。
- FlowGram 的表单能力与 Ant Design 组件之间应有明确的数据所有权，避免两套表单状态互相同步。
- UI SDK 的聊天、引用、附件和运行进度与管理编辑器分开交付，业务系统仅嵌入聊天时不加载编辑器框架。

## 最小验证范围

用同一文档处理流程覆盖条件、并行、foreach、变量引用和一个 Agent 节点，验证：

1. Mastra 定义导入编辑器后再导出，执行含义不变。
2. AI 修改指定步骤后，人工改动和未受影响节点的标识、配置、布局保留；可一次撤销 AI 修改。
3. 删除被引用节点、跨循环作用域引用、错误分支结构可得到明确提示，并在服务端拒绝发布。
4. 动态工具 Schema 能生成可用的 Ant Design 参数表单；变量选择与校验结果一致。
5. 执行事件能映射到原画布节点；带嵌套调用和多次循环的运行记录可区分。

若无需修改 FlowGram 核心即可完成这些项目，就继续采用 FlowGram。若必须长期绕开或重写其表单、变量及文档机制，应重新评估 React Flow，避免为未使用的框架能力承担适配成本。

## 固定版本实测补充

[FlowGram 1.0.15 往返实验](../research/flowgram-roundtrip-probe-2026-09-07.md)已接入真实画布并执行 Mastra 固定 Tool/mapping/helper 样例。数据可保存，但纯 data 修改没有默认字段撤销；默认位移服务与历史监听还有实例差异，公开 BaseService 入口及实际拖动已验证可用。普通 fromJSON 不删除旧节点，额外 metadata 也不是透明保存。

这些证据支持将文档装载、导出和历史入口封装成单独的适配层。尚未检验表单和变量机制，因此不能仅凭线性画布跑通就认定其全部复用收益已兑现。原先的主线选择保持不变，下一步用实际字段配置与变量引用验证这部分收益。

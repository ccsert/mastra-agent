# 资源放置与运行路由：首期讨论方案

日期：2026-09-07。状态：数据与接入产品方向已收敛，正式结论见[明确客户数据驻留与控制面访问边界](../../.scratch/agent-platform/issues/01-data-and-network-boundary.md)的 Answer。本文中的运行绑定、策略字段和协议细节仍为设计建议，尚未实现；租户、项目与身份映射另由身份决策负责。

## 已确认的前提

- 平台内使用与业务系统嵌入/API 均属于首期能力。
- 平台提供自身的运行与业务数据存储，也支持集中控制面管理客户私有 Runtime。
- 首期允许同一项目混合使用托管与私有资源：项目环境设置默认位置，知识库和工具可指定其他位置。
- 客户私有内容默认保留在私网，可以按客户配置的类别与范围授权传输。平台托管内容按托管配置正常保存。
- 客户可按模型服务和内容类别配置处理范围，允许自有模型或客户明确许可的外部模型处理获准内容。
- 首期由平台提供客户侧主动连接能力，客户按需安装轻量连接器或完整 Runtime。
- 平台运营默认仅查看运行状态；查看客户业务正文需要客户授予内容访问权限，平台托管内容同样适用。
- Agent、知识库与工作流分别作为能力保留；运行使用发布版本，Skill 按版本与资源范围授权执行。

## 已确认的位置规则与待细化设计

已确认以“项目的目标环境”设置默认位置，并允许知识库与工具指定其他位置。建议具体配置包含默认 Runtime、业务存储与数据传输政策。这里的目标环境暂指某个发布与使用目的地，例如测试或生产；它是否属于权限隔离层级，留待身份决策确定。

资源通常继承该环境的默认位置；知识库与工具可以显式绑定不同位置。这样同一客户可同时采用平台托管和客户私有能力，接入方也无需在每次调用时自行拼装所有服务地址。

| 对象 | 建议绑定规则 | 用户可以理解的行为 |
| --- | --- | --- |
| 项目目标环境 | 设置默认 Runtime、业务存储与传输政策 | 发布时能看见执行和保存位置 |
| Agent / 工作流发布 | 绑定版本及所需资源，校验这些资源在目标环境能否使用 | 发布前发现私有知识库不可达、工具未授权等问题 |
| 知识库 | 明确文档、切片与索引的位置，原型先验证这些内容位于同一存储域 | 知识库可保留在客户私网，检索结果的返回范围另受政策约束 |
| 工具 / MCP | 明确实际执行或连接位置及凭据引用 | 平台上的 Agent 可以通过获准连接查询客户业务系统 |
| Skill 版本与环境 | 包内容按获准分发范围到达目标 Runtime；固定内容与依赖版本 | 私有 Skill 不因目录可见就自动复制到平台 |
| 会话与运行 | 会话记录所属存储位置；运行开始时绑定主 Runtime、发布版本及输入输出位置 | 切换环境不会悄悄搬走已有历史，进行中的任务不会因默认位置变更而迁移 |

用户的本次选择确认了默认位置和知识库/工具的位置覆盖能力；表中的发布校验、运行绑定与变更处理细节仍是实现建议。项目/环境的权限层级、跨项目共享、自动迁移能力，以及旧会话后续运行与资源搬迁的具体操作仍需细化。

## 用一个业务例子检查方案

以下为讨论样例，尚未选为正式验收场景：用户在平台聊天中要求“查询本月订单，结合企业文档生成报表”。

1. 会话使用平台托管环境，平台保存对话和获准返回的报表。
2. 主 Agent 在平台 Runtime 执行；订单工具位于客户私网，企业知识库也可以位于私网。
3. 订单工具由具备客户网络可达性的连接器或客户 Runtime 执行；知识检索由知识库所在环境处理。
4. 只将客户已授权传输的工具结果或检索内容返回平台。调用工具的权限、把结果传给平台的许可，以及向模型服务发送这些内容的许可分别判断。
5. 缺少结果返回许可时，提供明确的不满足原因；可以另建以私有 Runtime 为执行位置的运行。私有运行的集中展示同样受数据政策约束，不能把切换 Runtime 当成自动放行正文。
6. 业务系统内嵌同一个 Agent 时，复用发布、资源授权及路由规则，并根据实际平台用户或应用/用户身份检查访问权限。

“每次运行固定主 Runtime”是建议的首期执行约束。远程工具或检索调用有独立的调用标识和结果状态；是否需要把任意工作流节点跨 Runtime 调度、迁移或恢复，属于更大的执行能力，未由本方案默认为已支持。

## 网络与控制面的边界建议

| 路径 | 建议职责 | 仍需取得的证据 |
| --- | --- | --- |
| 控制面与私有 Runtime | Runtime 主动建立受认证的管理连接，获取获准发布并上报管理状态 | 连接认证、离线行为和管理内容清单 |
| 平台或嵌入 UI 到执行服务 | 按授权资源取得可达的执行入口与短时会话凭据 | 浏览器网络、流式传输、附件与会话恢复 |
| 托管 Runtime 到私网工具或检索服务 | 通过客户获准的连接路径传递受限请求，明确执行身份与结果传输范围 | 连接器协议、幂等、取消、结果不确定与审计关联 |

管理连接的建立本身不意味着允许代理业务正文。控制面保存资源标识、版本摘要、环境绑定及获准的健康状态；名称、提示词、流程参数、错误详情可能含业务内容，需要按客户政策分类。具体允许集中保存的字段清单仍待收敛。

平台保存业务数据与平台运营人员能否查看正文分别授权。用户已确定平台运营默认仅查看运行状态，正文访问需要客户授予内容访问权限；具体权限分配与审计机制继续细化。客户授权传输某一类别内容后，在范围内正常执行，无需逐条对话或每次工具调用重复申请同一许可。

客户私有 Runtime 选择外部模型服务时，输入与输出仍可能跨越客户网络边界。用户已确认由客户按模型服务和内容类别配置其可处理范围，自有或明确许可的外部模型均受支持。具体模型端点、凭据引用、运行适配与费用治理在模型接入设计中确定；这项决定不是对任意第三方服务的通用许可。

## 混合使用中的内容处理建议

已经确定的是客户可按类别与范围授权指定内容传输。建议把具体许可表达为“什么内容、送往哪里、用于什么、是否保留”，在配置时确定，运行时自动校验。

| 行为 | 建议校验内容 | 例子 |
| --- | --- | --- |
| 业务输入送入客户私网 | 来源主体、目标资源、操作与输入范围 | 托管 Agent 向订单工具提交获准的查询条件 |
| 私网结果返回平台 | 目标环境、允许的结果字段/内容类别与用途 | 订单工具可返回订单总额；未经许可的明细不进入托管运行 |
| 平台保存结果 | 存储目的地、保留范围与期限 | 报表获准保存，不代表工具调试正文也应保存 |
| 结果用于模型处理 | 具体模型服务及其部署位置、允许发送的内容类别 | 允许向平台返回检索片段，不自动授权把片段发送给任意外部模型 |
| 运行信息进入控制面 | 允许的管理字段和经过分类的错误信息 | 健康状态可集中查询，原始工具响应与完整异常栈另按内容政策处理 |

以上是拟议的规则表达方式，不要求每次调用逐项人工批准，也不预设每位客户都要填写复杂策略。平台可提供模板，客户按环境或资源配置；批准范围内由服务端自动执行。模型、脚本及工具返回值不能自行修改这些许可。

许可应在内容离开来源环境前落实，未获准字段先排除或请求工具返回允许的投影。若无法可靠形成获准结果，返回明确的策略不满足状态，不能先把完整内容送至集中环境再做过滤。检索片段、摘要、报表和模型答案可能仍含来源内容；不能仅因格式改变就自动解除原有传输约束。

模型处理的首期政策已由用户选择：客户按模型服务与内容类别配置允许范围，既支持客户自有模型，也支持客户明确允许的外部模型；私网内容不进入未授权的模型服务。建议模型配置绑定实际服务端点和部署位置，模型重命名或切换供应商不能绕过目的地约束；具体鉴权与策略字段仍是待细化的实现。

## 已确认的私网接入与平台运营边界

用户已确认首期由平台交付客户侧主动连接能力：客户侧组件主动连接平台，承接获准的私网调用。仅需接入现有工具时可使用轻量连接器，需要本地 Agent、工作流或 Skill 执行时部署完整 Runtime。逻辑组件与部署设计见[Runtime 托管位置与安装方案](runtime-deployment-profiles.md)。

集中界面显示私有运行内容时，仍先检查客户的传输与查看政策。有相应授权可通过业务接入服务转发；不允许正文经过集中环境时，使用具备私网可达性的浏览器/客户侧界面。主动管理连接不自动授权业务内容转发。

用户已确认平台运营人员默认仅查看运行状态，访问客户业务正文需要该客户授予的内容访问权限，托管存储也遵循这一规则。建议状态信息包括健康状态、版本、资源用量及不含正文的故障信息；最终管理字段清单由内容策略细化。客户组织管理员如何分配权限、采用持续授权还是临时授权，由身份契约和客户策略细化，不预设逐次人工审批。

上述两项产品方向已确认。所需的受认证出站连接、代理兼容、流式传输与附件路径须经[主动连接原型](../../.scratch/agent-platform/issues/21-private-connection-prototype.md)验证；目前没有部署任何连接服务。

## 连接中断与策略变更的处理建议

- 私网工具或检索不可达时，返回可识别的不可达/等待状态；不自动复制私网内容、切换模型服务或改变资源位置。是否等待、多久超时由具体运行契约定义。
- 业务系统可能已完成写入而调用链失联时，记录结果不确定，通过工具幂等键或查询确认处理；不能仅依据连接失败就重新执行写入。
- 对内容外发，在每次发送前校验适用政策及有效期。策略更新有修订记录；客户 Runtime 断网时无法保证即时收到撤销，离线许可期限和停止边界由恢复契约明确。
- 撤销未来传输许可与处理已送达副本分别执行。平台已保存内容的删除、保留与审计规则需独立定义；不能声称一次撤销能收回已经发送的数据。

本节是待细化的设计建议，不是已经确认的可用性、恢复时间或撤销时效承诺，也不将这些行为归因于 Mastra 自动提供。

## 推进与验证顺序

1. 数据与接入的产品方向已收敛；具体管理字段、目的地/用途、保留和删除由[内容策略决策](../../.scratch/agent-platform/issues/20-content-policy-lifecycle.md)承接，连接协议与网络证据由主动连接原型取得，撤销时效由恢复契约确定。
2. 下一步明确客户/租户、项目、平台用户、应用及业务用户的授权关系，以及业务系统实际执行身份。
3. Skill 沙箱已有明确的授权与研究前提，可先进行范围有限的技术原型；资源路由、聊天嵌入、工作流映射与恢复原型按各自决策前置推进。
4. 将已确认的决定与原型证据整理成可实施规格，再拆分实施任务。本文不替代正式规格或首期验收标准。

与本方案相关的原型应至少观察：两种 UI 入口使用同一授权路由；无权调用或无权传输内容时明确拒绝；默认位置变更不改变已有运行；私网连接中断不自动复制内容或切换执行位置；托管资源不可跨租户读取。

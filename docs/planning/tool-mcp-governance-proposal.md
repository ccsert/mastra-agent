# 工具与 MCP 注册、发布和调用方案

日期：2026-09-07。对应[工具与 MCP 治理决策](../../.scratch/agent-platform/issues/05-tool-mcp-governance.md)。用户已采用业务写入默认确认、客户可配置自动写入范围的政策；据既有身份与版本要求采用以下工程边界。决策已关闭，协议和运行验证仍待后续原型。

## 核心分工

业务应用可以提交工具或 MCP 服务，平台为能力建立稳定目录和版本；授权 Agent、工作流及应用使用具体能力，Runtime 或连接器在获准位置调用。登记成功、目录可见、允许发布、允许调用分别表达，避免业务团队注册一次就向所有 Agent 开放全部操作。

建议首期支持 HTTP/OpenAPI 工具和远程 MCP 服务。必须本地进程启动的 MCP 由资源所在 Runtime 的受管环境承接，登记固定程序版本与启动配置；集中控制面不直接执行第三方提供的命令。传输协议的精确版本和 SDK 支持矩阵在接入原型中固定。

平台内直接使用与业务系统嵌入共用这一规则，平台 Agent 可以调用已授权业务写入。轻量连接器承接私网连接和受限工具调用；完整 Runtime 还负责本地 Agent、工作流、知识库或 Skill 执行。客户不需为只有一个私网工具的场景先安装完整执行栈。

## 五类对象

| 对象 | 保存什么 | 变化影响 |
| --- | --- | --- |
| 工具服务登记 | 所属租户/项目、来源应用、位置、受控 endpoint/启动配置、维护责任 | 不承载长期 Secret 明文，不自动获得执行权 |
| 能力版本 | 工具标识、说明、输入/输出 schema、能力快照摘要、适配器版本 | 语义或 schema 改变形成新候选版本 |
| 执行绑定 | 版本、环境、Runtime/连接器、凭据引用、目标网络、实际业务身份映射 | 确定在何处、以何身份调用；凭据轮换不要求复制 Agent |
| 使用授权 | 哪些应用/Agent/工作流可用哪些动作和数据范围 | 版本可固定，授权仍能收窄或撤销 |
| 调用与批准 | 发起主体、具体参数摘要、动作、版本、业务幂等键、批准与执行结果 | 重试与恢复关联同一业务意图，不用模型文本当审计依据 |

以上是平台对象，不要求第三方修改 MCP 协议字段。名称映射应避免同名工具冲突，并在面向模型的最终工具集中保留稳定且唯一的名称。

## 注册到可用的流程

```mermaid
flowchart LR
  D[应用提交登记] --> V[所属位置发现与验证]
  V --> C[能力快照候选]
  C --> P[有发布权限者发布版本]
  P --> G[绑定使用授权与执行环境]
  G --> R[Runtime 按绑定调用]
  R --> O[结果校验与内容策略]
```

发现由能到达服务的位置执行。私网 endpoint、schema 和说明也可能含客户信息，上报的目录字段遵循内容政策；不能以“只是元数据”为由默认向集中环境复制。连接验证只做协议/能力发现和明确的只读健康检查，不能为了“测试可用性”自动执行业务写入。

建议资源维护者可以同时拥有提交、验证和发布权限，降低日常接入成本；若客户要求分权，再配置不同角色。发布的关键是版本与责任可追踪，不强制每个工具都由平台运营人工审批。

对于 MCP，`tools/list` 支持分页，服务器可通知能力列表变化，工具说明包括 schema 和可选 annotations；来自非受信服务的 annotations 不能直接当作安全结论。平台因此保存发现快照并自行确定动作政策，不凭工具自报 `readOnlyHint` 自动放行。[固定 MCP 2025-11-25 Tools 规范](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)。此处固定规范作设计依据，不表示已选定所有客户的协商版本。

## 运行时检查与结果处理

调用前检查主体与用途、发布绑定、资源范围、批准要求、策略有效性和执行位置。模型只能在下发的已授权工具集中选取工具，不能自行指定其他租户、endpoint、Secret、Runtime 或任意代码。执行方在本地再次检查绑定与允许目标，避免把集中目录可见性当作执行授权。

应用服务任务使用授权服务身份；用户委托任务同时受应用和用户范围限制。业务系统实际接受的凭据由执行绑定决定，平台记录其实际主体，不默认把平台用户变成业务系统管理员。长期凭据留在资源所属位置，模型和生成提示词中只出现必要的能力描述。

MCP 的 HTTP 授权涉及资源面向的 token 与服务端校验。平台自身访问令牌不应不加判断地转交任意第三方 MCP endpoint；应使用目标认可且受限的独立凭据或经验证的交换路径。[固定 MCP Authorization 规范](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)。平台 AppID/AK/SK 与 MCP 服务的认证是两段连接，不合并成一个全局通用 Secret。

结果按能力 schema（存在时）校验，并按[内容策略方案](content-policy-lifecycle-proposal.md)处理结构化字段、文本、附件及嵌套内容。只过滤 JSON 字段但把同一原文保留在文本内容或错误堆栈中仍会泄露；结果裁剪须覆盖实际发往目的地的整份消息。被裁剪结果明确标注，不伪装成完整业务结果。

## 已采用的写入与审批默认值

| 动作 | 建议默认 | 允许客户配置的范围 |
| --- | --- | --- |
| 已验证只读查询 | 在版本与数据范围授权后自主调用 | 可对敏感数据查询增加批准要求 |
| 业务写入 | 首次接入默认要求明确动作批准 | 客户可按指定工具版本、动作、对象范围和额度授权自动执行 |
| 影响不明的能力 | 在维护者明确动作类型和政策前不进入自主工具清单 | 通过登记验证补齐，不信任模型或服务自报风险等级 |
| Skill 内调用业务工具 | 复用该业务工具政策 | Skill 执行许可不绕过业务动作审批 |

用户已选择上述默认值。已获版本与范围授权的 Skill 不需要每条脚本人工批准，脚本调用业务工具时继续受工具动作政策约束。

批准应绑定调用主体、工具版本、目标对象、参数摘要、动作范围和有效期；重要参数变化时原批准失效。后台应用任务若需持续自动写入，应提前取得明确的动作政策，不能用虚构的“用户已点击批准”继续运行。UI SDK 与 iframe 需要展示同一批准对象及状态。

## 变化、失败与撤销

| 事件 | 建议行为 |
| --- | --- |
| MCP 新增工具或 schema 改变 | 新发现快照产生候选变更；已发布 Agent 不自动获得新能力或新 schema；发布前展示差异 |
| 远端只保留最新实现 | 固定的是平台契约快照，不能声称远端行为可回滚；要求服务版本化 endpoint/实现，或检测不兼容后停用并报告 |
| 同名工具被移除 | 旧绑定显示能力不可用；不自动找另一个同名工具替代 |
| 暂时不可达 | 区分连接错误、调用超时和结果不确定；按能力允许的重试规则处理 |
| 写入发出后丢响应 | 标为结果不确定，使用业务幂等键/查询接口确认；不能把超时直接当未执行再次写入 |
| 注册应用被停用 | 停用其凭据与受影响能力的新增调用；哪些独立移交的能力可继续由显式所有权与政策决定 |
| 撤销资源许可 | 停止新调用；进行中调用和离线执行按恢复/租约契约处理；保留审计不等于允许继续读取正文 |

工具自身的幂等声明不等于业务系统实际支持。平台调用 ID、工作流 step ID 和业务幂等键分开记录。取消和重启恢复的准确语义由[Runtime 恢复决策](../../.scratch/agent-platform/issues/07-runtime-failure-contract.md)统一定义。

## 后续原型必须观察的结果

用合成查询和写入工具验证：未授权登记者拒绝、分页发现完整、同名冲突可定位、schema 更新不漂移、旧实现缺失不静默替代、错误凭据/租户/目标拒绝、批准后的参数变化拒绝、写入超时结果可核对，以及停用后的新调用被拒绝。私网路径同时测主动连接与内容回传限制。

工具治理决策已关闭，业务写入默认政策由用户确定；实际 MCP 客户端、连接器与目标服务版本仍待原型固定。Runtime 恢复和版本发布契约继续承接进行中调用及升级处置。

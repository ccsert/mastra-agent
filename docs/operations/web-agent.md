# 网页 Agent 的运行方式与边界

网页 Agent 复用 Mastra Workspace、AgentBrowser 和 durable Agent；聊天复用 assistant-ui 的消息、编辑器、推理与工具组件。启用网页工作区前先准备独立的任务容器镜像。

## 启动

```sh
docker build -f deploy/web-task.Dockerfile -t platform-web-task:local .
docker image inspect platform-web-task:local --format '{{.Id}}'
```

将第二条命令返回的不可变镜像 ID 配置为 Runtime 的 `TASK_SANDBOX_IMAGE`，并配置绝对路径 `TASK_WORKSPACE_ROOT`。`pnpm dev` 传递这两个变量；独立 Runtime 可读取 `.env.runtime`。容器化 Runtime 使用 `deploy/runtime.web.compose.yaml`，宿主与 Runtime 内的工作区路径必须一致。

Runtime 管理 Docker，任务容器不挂载 Docker socket。每个执行尝试创建独立容器，只挂载所属会话的 `project/`；无外网，根文件系统只读，限制 CPU、内存、进程数与临时目录。任务文件保存在宿主工作区，退出时清理浏览器、连接转发和任务容器。

在 Agent 编辑器中启用网页工作区。模型必须支持工具调用，使用截图评审还需配置真实可用的视觉模型。发布后，新会话固定使用该版本；修改 Agent 配置不会改变已有会话的发布快照。

## 预算与步骤

主代理可配置 1–80 个模型步骤，子代理最多 20 步；时间上限 2 小时，总模型请求上限 240，总 Token 预算上限 200 万。10/30/80 是容量预设，不要求 Agent 跑满。模型重试与子代理请求共同计入当前 Run 预算，进程恢复不清零。新用户回合会产生新的 Run 预算。

Token 在发起请求时预留，收到服务端 SSE 用量后结算。服务端未报告用量的请求保留预留值；界面将它与真实用量区分。图像按图片预算预留，不把 base64 字符数当作文本 Token。

原始事件持续保存。模型上下文使用 Mastra TokenLimiter 裁剪近期内容，同时保留原始任务锚点和最新持久任务进度；裁剪记录包含移出的消息 ID。这是上下文裁剪与工作记录，不是已经集成的自动语义记忆或完整知识召回。

## 网页与交付

任务可读写文件、运行容器命令、启动本地服务器、操作真实 Chromium 并截图。预装 Node、Vite、React、vite-plugin-singlefile；无外网安装步骤。创建本地可写的 `node_modules` 并链接预装包，避免让 Vite 缓存写入只读镜像。

`browser_check` 检查视口、横向溢出、部分名称/图片属性与已观察的页面异常。它不等同于完整无障碍审计、Lighthouse 或人类审美评审。截图通过实际图片输入传给视觉模型，页面结构检查不能代替视觉判断。

`workspace_checkpoint` 保存、列出、回退候选版本，最多 16 个。标记最佳版本必须附证据；同一个执行工作区的工具串行操作。只读评审期间主代理暂停文件和浏览器操作，子代理不能使用平台写工具、Skill 脚本或命令工具。评审仍需绑定版本并说明证据与检查范围。

`workspace_publish` 保存真实 HTML/PNG/ZIP/JSON/文本，单文件 5 MiB，每轮最多 100 个/50 MiB。工作区在工具调用前后检查 1500 个文件/50 MiB；这属于执行边界检查，并非文件系统的硬磁盘配额。检查点有独立副本，运维需为持久目录配置容量与保留策略。

HTML 预览在无同源权限的 sandbox iframe 中运行，禁止网络、嵌套 frame、表单外发和外链资源。使用单文件内联构建以获得完整预览；原始 Vite 入口不能代表已构建网页。源码 ZIP 与截图可从成果区下载。

## 中断、恢复与消息编辑

平台租约决定唯一执行者。原生快照保存在控制面，Runtime 不直接访问平台数据库。意外进程丢失时，在截止时间和恢复次数限制内重新 claim 并调用 Mastra recover。工具回执表防止已确认的调用重复执行；执行后回执丢失的调用标为结果未知，并停止自动重复操作。

短暂控制面断连可重试有租约和幂等键的保存操作。Claim 不自动重试。用户取消、预算到限与无法确认的副作用都不能靠恢复绕过。

消息编辑通过原生编辑器提交服务端分支请求，只复制所选用户消息之前的历史，再发送修改后的内容。原会话及后续回复保留，重复提交幂等。历史工具和子代理链接保留原会话来源。网页工作目录按会话隔离，消息分支不隐式复制原会话的最新文件。

运行中的“补充要求”单独保存到当前 Run，最多 8 条，每条 2000 字。执行器在下一次模型请求前读取当前会话最近 8 条补充要求；完整补充记录仍留在所属 Run 的成果区和历史查询中。“执行器已读取”只代表读取状态，不代表修改已落实。如果在最终模型响应期间补充，本轮可能来不及处理，下一用户回合会再次读取。取消和结束后的 Run 拒绝新的补充提交，原提交可以用同一幂等键查询结果。

编辑分支会重建并保留之前失败/取消轮次中已经记录的回复，保留原会话的轨迹链接。历史回放只合并连续的打字片段，原始事件不改写。终态元数据在平台提交结果后通过 SSE 返回，聊天可直接显示预算、步数或取消原因。

## 已知验证边界

- 80 个自主模型步骤与 80 个用户回合是两类实验，不能混报；协议模型压力回归不代表真实模型作品质量。
- hard crash 的恢复回归与 graceful SIGTERM 不同：当前正常停止 Runtime 会中断活动执行，不宣称升级完全无感。
- 自动语义记忆、多模型盲评、Lighthouse 及多次真实 80 步对照实验仍需独立验收。
- Mastra 固定 1.64.0，使用公开 pruneSnapshot 适配保留恢复需要的前驱输入，另有 TTLCache 空条目的两行补丁。升级必须重跑 Skills、长步骤、图片和新进程恢复回归。

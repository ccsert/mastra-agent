## 能力与修复

| 范围 | 本次行为 |
| --- | --- |
| 模型请求 | 每个 HTTP 尝试保留独立请求编号，包含失败、重试和仅调用工具的响应；Runtime 的 `prepareStep` 记录生成编号，避免把网络重试序号当成下一次模型生成。 |
| 推理 | 开启 `toAISdkStream.sendReasoning`，流事件与最终消息均持久化；轨迹检查器显示推理，聊天直接复用现有 assistant-ui 推理组件。 |

| 工具 | 参数、结果、调用 ID、本次请求中的 Schema 可查看；工具可以定位对应模型请求。Workspace 原生 `skill`、`skill_read`、`skill_search` 加入已知 Skill 计时来源。 |
| 用量 | 显式开启 OpenAI-compatible `includeUsage`，保留逐次生成与整轮用量、结束原因。未知用量不按 0 展示；旧 Mastra 的空用量总计 0 在读取模型中归一为 null，原始事件不重写。 |
| 运行与消息 | 每轮保留运行状态、起止时间、版本、Runtime、指定 Skills、关联消息 ID、最终保存的消息与采集缺口；缺失流式正文但仍有保存的答复时，标注来源后展示该答复。 |
| 分页 | 后端为每轮返回事件数、最后序号和读取时间；事件 API 增加 `through` 上界。最新轮次与链接定位的轮次自动续读，不在 500 条事件处停住。未加载的历史尾部显示“待加载”，不误标成仍在运行。 |
| 搜索与导出 | 搜索覆盖正文、推理、请求、工具定义、参数、结果和关联 ID，搜索结果不再被折叠组藏住；提供加载完整会话和完整导出，校验事件数量、分页前进与读取边界，支持取消和失败重试。 |
| 阅读交互 | URL 保留 `runId` / `recordId`；刷新可恢复具体记录。检查器支持前后记录、复制、工具关联定位。轮询不重置用户阅读位置；最终消息先呈现正文，原始消息与协议数据折叠保留。 |

后端对观察事件做契约校验，并将类型化 `observation` 与原始 `chunk` 同时返回；OpenAPI 和 SDK 已同步。此次契约补充不需要新增数据库迁移。

## 完整性的含义

“完整导出”覆盖本次读取开始时的全部轮次，每轮按其 `checkpoint.lastSeq` 读取完整事件，附带原始协议、保存的消息与合并后的记录。这是带有逐轮读取边界的导出，不是跨多次 HTTP 请求的数据库全局快照。运行中的导出标注 `live`，导出后新增的轮次与事件需要再次读取。

历史未采集的推理、请求、计时、工具 Schema 不能凭当前配置补造。旧请求没有生成编号时，输出关联仍只能按顺序推断，并在来源中明示。读取成功表示已加载全部已保存记录，不表示历史采集没有缺口。

本轮没有宣称实现授权决策审计、嵌套 Agent/工作流执行树或上下文压缩生命周期；这些需要对应后端先产生可关联的事实，不能用前端猜测替代。生成文件、引用和扩展协议内容保留为可检查记录。

# Agent 应用协议第一阶段交付 · 2026-09-14

## 结果

已落地框架无关的应用协议与 SDK，并将平台任务台接到同一个后端执行通道。接入应用依照业务动作提供状态和 handler，不需要平台组件库。内置平台适配现有 React 表单/页面处理函数；独立示例使用纯 JavaScript 与 DOM。第一阶段覆盖状态读取、视图切换、检索、草稿编辑和校验。

入口：平台助手 → 新任务 → 应用协作。管理员可登记应用，用户选择当前任务的应用及页面，默认只开放读取/视图；草稿需单独授权。第三方页面位于右侧抽屉，聊天位于左侧，操作时显示 BorderBeam 和状态，并可随时停止。修复全局任务台缺少项目权限上下文、模态框居中导致聊天被抽屉遮挡，以及无授权握手错误提示被断连提示覆盖的问题。

新增 `platform_app` 工具负责 inspect / describe / act / result；动作详情按需发现。服务端权限检查、schema 校验、短租约、单窗口/单动作、版本检查、幂等请求及真实回执均贯穿运行器与浏览器。用户在执行间隙修改页面时拒绝旧动作；多字段填写遇到人工修改，停止剩余字段并保留已修改内容。结果未知不自动重放。

协议 API、运行步骤及第三方开发者说明：[`agent-application-sdk.md`](../development/agent-application-sdk.md)。

- 内置平台运行 `398934de-6d74-4848-a457-1116dc13b38c`，会话 `2bfd9087-18c2-46da-984f-8a156559f089`：真实模型执行一次 `agent.draft.patch`，同时填写名称、适用场景与指令；三个实际 React 字段与回执一致，没有创建/保存/发布资源。

示例登记保留在本地项目供继续体验，示例服务器独立启动；不自动随 `pnpm dev` 启动。上述结果仅代表当前本地验收，未提交、推送或部署。

## 明确边界

尚未覆盖持久化业务写入审批、所有常用组件适配包、第三方 OAuth 委托、原生 WebMCP、独立标签页/浏览器扩展 transport，或未接入旧应用的视觉自动化。SDK 目前是本仓库 workspace 包，尚未发布 npm。应用需要配置允许嵌入的 origin，并在自身业务处理函数中复核登录与权限、遵守取消信号。应用声明的 effect 不是第三方代码安全性的证明；登记应用仍需应用方与管理员维护可信实现。

# 会话多轮轨迹与运行记录合并

日期：2026-09-09。接续 [轨迹透明度修复](trajectory-transparency-fix-2026-09-09.md)。本轮再次对照已启动的 DSH 3081：同一会话共享系统提示词，按用户轮次阅读，工具定义从系统详情进入。

## 用户可见的变化

- 会话页使用同级“对话 / 轨迹”标签，`?view=trace` 驱动视图；切换、刷新和浏览器返回保留正确位置。
- 移除左侧运行卡片和运行抽屉。轨迹列表合并整个会话，用户输入行标记“第 N 轮”；不再展示模型内部步骤标题。
- 主列表显示系统、用户、助手、工具和错误记录。重复的模型请求上下文移入对应模型记录的“请求内容”详情；无正文的工具调用请求依然可检查。
- 初始系统提示词全局只显示一次；“工具”标签显示首次实际请求注册的名称、说明及参数 Schema。后续请求也各自保留工具定义，不将后来的工具混入初始配置。
- “运行记录”每会话一行，展示轮数、最近一轮状态与最后运行时间，进入同一个会话轨迹。旧 `/runs/:id` 地址仍可进入所属会话并定位该轮。
- 用户输入详情的“本轮运行”保留运行 ID、Runtime、发布版本、执行状态和指定 Skills。
- Session 日志导出合并后的消息、请求和工具调用，不逐条输出 `text-delta`。底层协议仍保留于开发者诊断下载入口。
- 具体会话页面去掉通用标题介绍区，把可用高度交给对话和轨迹列表。选中记录前列表全宽，选中后显示可调宽详情。

## 数据与工程边界

Run 仍是独立执行与审计单元，本轮增加会话读取模型，没有合并数据库行或修改历史记录。轮次按 Run 创建时间与 ID 稳定排序；查询在只读、可重复读事务内保持初始配置、轮数、当前页及事件的一致性。同一事务连接内串行读取，避免并发调用 pg client 的弃用行为。

会话摘要使用稳定游标分页；轨迹默认最近 10 轮，可向前加载。每轮初始最多 500 条事件，存在后续事件时明确显示加载入口。按 Run ID 与事件 seq 去重，未加载完整时导出标为不完整。长回复从运行中转为终态时重新读取尾部，避免丢失最后的模型输出。

新增 OpenAPI `getConversationTrace`、`listConversationRunSummaries`，SDK 由 HeyAPI 生成。原始 Run 与事件接口保留。会话读取沿用项目、租户、用户和调用入口权限边界，未扩大正文访问权限。切换会话、项目或退出轨迹时取消旧查询；聊天 runtime 在标签切换时保持挂载。

旧运行只能从不可变发布快照恢复工具绑定，动态 Skill 工具若没有保存 Schema，则只显示已观察到的调用名称并注明定义缺失，不能用当前工具定义替代。用户原会话 `d33f13e6-4ae0-4818-ac29-e88aee574eba` 已确认合并为两轮，两个输入均存在；首轮属于上述历史数据情况。

## 实际验证

使用现有内网 Qwen 模型与授权 Skill，在独立合成会话执行两轮，没有调用真实订单系统：

- 会话：`21b8b99e-255e-4ce1-9dfa-a1d3e3ce0163`（多轮轨迹 · 合成验收）。
- 第一轮：`b041a9fe-1b82-496f-9eec-1cb43252733a`，succeeded；调用 `skill`、`skill_read`、`run_skill_script`，合成订单数 2、总额 120。
- 第二轮：`93ef0e69-dcbd-467b-bc48-0380a1ce96e9`，succeeded；实际请求包含上一轮历史，不再调用工具，回复订单数 2、总额 120.00。
- 会话摘要只有一条、runCount 为 2；语义轨迹有两个用户输入、五个模型请求、三个工具调用。
- 首次实际模型请求保存四个完整工具定义：`run_skill_script`、`skill`、`skill_search`、`skill_read`；投影检查确认每个模型记录均保留请求，Session 日志无 `text-delta`。

浏览器使用 Codex CUA 的导航、原生 AX 和截图，没有使用 Playwright。实际截图核对了最新版会话页面高度、多轮合并列表、分类与内联详情，确认不再展示运行卡片、步骤标题及重复上下文行。随后在本机 127.0.0.1 完成登录与深链接恢复，实际点击确认系统详情四个工具及脚本参数 Schema、第二轮请求中的前文、用户详情的本轮运行信息、按会话合并的运行记录、摘要进入原会话、对话中两轮输入/回复以及旧运行链接定位第二轮。前期 CUA 曾多次超时，恢复后补完上述关键路径。

检查结果：

- `pnpm build`、`pnpm lint`、`pnpm architecture:check`、`pnpm sdk:check` 通过。
- 前端全量 45/45 通过；最后运行信息详情与样式整理后，轨迹针对性回归 6/6 通过并重新构建及类型检查。
- 后端全量 44 通过、2 跳过；最后事务顺序调整后，相关集成测试 5/5 通过，并重新读取两个真实会话验证。
- 两个跳过项为需要专用镜像环境的 Docker 隔离测试，本轮不计为通过。真实两轮样例的授权脚本实际执行成功。
- 控制台在 `*:5179` 提供局域网访问。本轮期间本机网卡地址从 `192.168.110.151` 变为 `192.168.50.31`：新地址和 127.0.0.1 的 HTTP 均为 200，旧地址已不可达；最后浏览器完整交互验收使用本机地址。构建仍存在此前的 chunk 大小提示。

当前概览表示调用顺序，时长是控制面接收事件跨度。模型原生耗时、Token 统计、完整重试关联、轨迹虚拟化等仍属于后续工作，本轮未实现 DSH 的全部观测能力。

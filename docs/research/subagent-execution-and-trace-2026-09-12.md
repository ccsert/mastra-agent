# 子代理执行与完整父子轨迹（2026-09-12）

本次把子代理补为真实执行能力：主 Agent 可以委派独立任务，子代理分别请求模型、调用工具，交回结果后由主 Agent 汇总。轨迹展示实际执行记录和关联 ID。

## 使用方式

在 Agent 编辑器中开启「子代理协作」，设置每轮委派次数、并发数和每个子任务步骤上限，然后发布新版本并新建会话。默认不开启，已有会话仍使用创建时的发布版本。

- 每轮最多 1–8 个子任务，同时执行 1–4 个，每个子任务最多 1–5 个模型步骤。
- 子代理沿用同一发布版本的模型、工具、Skills 与知识库授权，只接收分配的任务。父代理的业务背景和约束保留，但调度身份、委派和汇总职责明确属于父代理。
- 子任务共用父任务的截止时间与事件预算，不会因委派获得无限执行时间。
- 支持一层子代理。子代理没有 `delegate_task`，不能递归委派；没有跨模型或指定其他已发布 Agent 的路由。
- 取消父任务会停止正在执行和排队的子任务。子任务失败会记录结果并释放并发名额，主代理可以结合失败信息继续处理。

本地已创建并发布测试 Agent「子代理协作验收」v1，ID `1664d3e0-0616-42c1-a4a2-80f680e79965`。仅使用合成算术输入与 `sum_values`。

## 执行与记录

`apps/runtime/src/agents/delegation.ts` 提供每轮独立的有界调度器，通过普通 Mastra `createTool` 注册 `delegate_task`，复用现有 `executeJob`。没有冒用 Mastra 原生 supervisor API；这样模型请求采集、工具钩子、Skill/MCP 授权与取消逻辑都继续走已有执行入口。

新增 `data-subagent` 生命周期事件，以及 `data-subagent-event` 子事件封装。每个子任务有独立 UUID，显式关联父 `toolCallId`；子事件保留原始 chunk、实际产生时间、类型化请求/工具/用量观察。所有事件存放于父运行的同一有序日志，由现有会话鉴权和完整导出覆盖，不新增数据库子运行表。

用户取消执行后，事件传输保留有限的收尾窗口，让子任务取消终态先持久化，再结束父运行。断连、租约过期或历史采集缺失时仍可能缺少终态，界面明确显示未完成，不推测成功。

## 轨迹交互

- 结构为：轮次 → 主模型请求 → 子代理 → 子模型请求 → 推理、正文与工具；输入与终态保留在各自子任务下面。
- 子代理概览包含分配任务、状态、模型、步骤上限、可用工具、入队/开始/结束时间、返回结果和明细导航。
- 全树可折叠；搜索保留命中项的全部祖先；概览导航和详情双向定位能展开所有祖先，重复定位同一记录也有效。轮询不覆盖手动折叠状态。
- 子请求只与同一子任务的上一次请求比较；上下文中的工具结果也只定位到同一子任务。请求、工具和模型消息 ID 即使跨子任务复用也不会串线。
- 父用量、每个子任务用量分别保留供应方报告值。轮次汇总仅在所有参与执行的用量完整时求和，未报告保持未知；不会重复加计子任务终态。
- 保留固定 56 px 行高，详情在独立检查器阅读。子记录 URL 包含作用域，刷新能恢复原位置。

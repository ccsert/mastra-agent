## 实际观察与操作

使用 Codex 浏览器控制的 AX 与截图，没有调用 Playwright。已操作对话/轨迹切换、工具行、参数/结果/Schema/计时详情、实际时长开关以及轮次折叠。

1. 会话标题旁的“对话”和“轨迹”是同一个会话的两个视图。轨迹同时展示系统、用户、上下文、模型请求与工具，连没有回答文本的模型请求也占一条记录。
2. 记录区域是紧凑表格，长内容先给单行预览；选择后在右侧检查器展开。检查器宽度可拖动调整，关闭后还原阅读空间。
3. 工具检查器有概述、参数、结果、Schema、计时。参数和 Schema 使用 JSON 树；结果显示真实文件内容。计时展示来源，此次 read 显示 11 ms，并带开始时间。
4. 顶部概览按输入、模型、工具分层；可在等宽操作与实际时长之间切换。它用于定位事件，不是装饰色条。
5. 可收起轮次或调用、搜索轨迹；折叠后保留摘要和当前检查器。页尾统计来自实际模型请求，此次显示 1 轮、2 步、LLM 16.5 秒、输入约 21.5K/输出 288 tokens。

这些数值描述一次本地样例，不是平台性能指标。截图已在本轮工具输出中实际查看，未另存为仓库中的截图文件。

## 本轮平台改动与明确差距

聊天部分先复用 assistant-ui 官方组件：SlashCommandAdapter + ComposerTriggerPopover、ToolFallback、GroupedParts + ToolGroup、Reasoning。来源、许可证、适配点记录在 `apps/console/src/shared/assistant-ui/UPSTREAM.md`。保留现有 Skill 版本授权、结构化选择参数和知识来源展示。

运行详情改为调用顺序概览、紧凑记录列表、可调整宽度的右侧检查器。支持搜索、收起步骤，检查器提供概述、参数、结果/错误、计时和原始事件。点击概览可以清除过滤、展开并定位记录。

这只是利用已有事件完成的界面调整，尚未达到 DSH 的完整能力：

| 能力 | 当前平台情况 | 后续需要的真实实现 |
| --- | --- | --- |
| 模型请求，包括无文本请求 | 主要投影现有 text/tool/error 事件 | Runtime 记录 model request 生命周期、request ID、所属轮次与父子调用 |
| 请求上下文与工具 Schema | 未保存请求级快照 | 按客户内容权限记录并读取获准快照，不能事后用当前配置替代 |
| 时长、首 token、usage | 仅有控制面接收时间 | Runtime 产生开始/结束/首 token/usage，保留来源与时钟语义 |
| 时间线 | 本轮只提供等宽“调用顺序” | 有真实 span 后实现时间轴、并行关系和聚焦导航 |
| 对话和轨迹相互定位 | 仍以运行详情链接及现有入口访问 | 会话同级视图与 message/run/event 的路由定位 |
| 超长轨迹 | 现有分页与完整性标记仍保留，渲染未虚拟化 | 完整事件查询与虚拟列表、按需读取大正文 |

不把接收跨度标为模型推理耗时，不为缺失的 Token、Schema 或系统上下文填充样例值。后续重点是补 Runtime 采集与权限查询契约，再继续完善会话轨迹视图。

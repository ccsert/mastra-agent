# 会话轨迹读取模型与提问导航 · 交付

基于 `2918106`，解决轨迹视图进入慢的问题，并为每轮提问提供快速跳转入口。

## 问题

轨迹接口把「轮次列表」和「事件全文」绑定在一起：每页每个轮次携带最多 500 条原始事件 chunk。首屏 head 查询最多 5,000 条 chunk 才能出第一屏；运行中每 3 秒整页重拉；挂载即并发补全所有 `hasMoreEvents` 轮次的尾部。加载进度以左上角文字条呈现，位置突兀。

## 改动

- `TraceQuery` 新增 `events=summary|full`（默认 `full`，向后兼容）。摘要模式跳过事件 LATERAL 查询，轮次仍携带 run 元数据、checkpoint（事件计数与 lastSeq）和已存消息；`hasMoreEvents` 由 checkpoint 计数推导。
- Console 的 head 与历史分页全部改用摘要模式；轮次事件改为按需：运行中轮次、焦点轮次、用户显式请求的轮次，以及时间轴可见窗口相交的轮次才通过既有 reader 队列（并发 3，带缓存）补全事件。完整窗口没有缩放信息，只预热最新 8 轮，其余以摘要行呈现并显示「载入明细」入口。
- 会话记录列表左侧新增提问导航栏：每轮显示轮次号、状态与用户提问摘要（来自 `run.inputText`），点击即按需加载该轮事件并跳转聚焦；明细未加载的轮次显示标记点。
- 加载指示改造：移除左上角横幅与顶部补全提示条，改为工具栏末端的紧凑状态芯片（已加载轮数/事件数/待补全轮数、取消与重试入口），首次加载显示列表区骨架屏。
- 「加载完整会话」（导出路径）保持 full 模式逐页读取，行为不变。

## 验证

`pnpm check` 退出码 0：后端/协议测试 153 通过、4 跳过（沙箱镜像未配置），Console 测试 170 通过。新增回归覆盖：

- 集成：`events=summary` 返回空事件、`hasMoreEvents=true`、checkpoint 与消息和 full 模式一致。
- Console：摘要分页请求携带 `events=summary`；摘要轮次不出现在预热范围时不发起事件请求，点击导航栏后按需加载并渲染明细。
- 既有 33 项轨迹/导航/加载测试全部通过（部分查询因导航栏引入同文案元素改为 All 变体）。

## 边界

- 时间轴窗口与轮次的映射使用运行创建时间域的线性插值近似；窗口缩小后如果某轮未被命中，仍可通过导航栏或「载入明细」手动加载。
- 浏览器视觉验收（导航栏布局、骨架屏、状态芯片）需要在已登录会话中确认；本轮的界面行为由 Console 测试覆盖。
- 摘要轮次的行详情显示「0 次请求 · 明细未加载」，加载后自动更新，不伪造计数。

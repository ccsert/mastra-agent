## 本次实现

### 可发布的任务计划

Agent 编辑器增加「记录任务计划」，保存、发布后对新会话生效。默认关闭，旧发布快照兼容。声明不支持工具调用的模型不能启用计划；`update_plan` 是保留工具名。

工具接收计划标题、更新原因、完整任务清单以及 `baseRevision`。任务使用稳定 ID 和独立的 `pending / in_progress / completed / blocked / cancelled` 状态，可附说明。每版最多 20 项，每个执行作用域最多 100 版；更新串行处理，陈旧修订拒绝，重复任务 ID 拒绝。事件写入失败时不会推进修订号。

计划通过类型化 `data-task-plan` 事件持久化，并作为真实工具返回值进入消息历史。因此断开浏览器后仍能在历史对话、轨迹和完整导出中恢复版本。计划节点关联实际工具调用 ID 和发起的模型请求，可从卡片定位、折叠、筛选和回溯上一版。变化列表区分新增、状态变化、内容变更和移除。

计划范围是单轮执行；子代理有独立修订序列。同一会话下一轮会建立新的计划范围，历史版本保留。本次没有增加跨轮共享的可变待办数据库。任务状态由 Agent 报告，不自动验证业务完成，也不产生审批授权。

### 对话与结果阅读

- 计划和委派使用 assistant-ui 的独立工具 UI，直接显示卡片，不需要先打开通用工具分组。
- 子代理卡片显示任务名称、分配内容、结果与执行轨迹入口；失败、取消和拒绝不会因为工具正常返回而被渲染成成功。摘要使用 Markdown，原始参数与结果仍可展开。
- `run_skill_script` 显示脚本入口、Skill 版本、退出码、标准输出、标准错误和完整记录；有效 JSON 标准输出可以结构化阅读。
- 扁平对象数组使用 Ant Design Table，支持分页、横向滚动与固定高度。包含标量摘要及行数组的常见结果封装也会展示摘要字段和数据表；任意复杂嵌套仍保留 JSON，不猜测业务含义。
- 历史计划卡片不持续播放“进行中”动画；原有消息操作区的固定布局保持有效。

### 并行轨迹

按实际时长查看时，同类事件按照真实起止时间分配不重叠的显示行。两个并行子代理及各自模型请求能够分别看到、点击；序列模式仍保持原顺序。计划拥有独立分类与时间线。详情显示子任务上下文，避免同名请求混淆。

事件缺少终点时只显示观测点，最小视觉宽度不会变成虚构执行时长。历史时间与用量继续保留来源和未知状态。

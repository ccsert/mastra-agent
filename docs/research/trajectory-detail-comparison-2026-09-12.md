# 轨迹细节第二轮改进（2026-09-12）

## 对照 DSH 后的具体差距

只增加事件字段和详情标签仍然不够。浏览器中的 DSH 请求概述直接呈现模型、状态、工具/子工具数、输入与输出拆分、缓存、推理、首 Token 和吞吐；列表按轮次、请求和内容块组织。其本地源码 `ui-trajectory/trajectory-assistant-definition.ts` 保留独立内容块；`trajectory-tool-definition.ts` 通过实际父子调用 ID 建树，不以文本或显示顺序冒充因果关系。

## 本次实现

- 请求下保留独立推理与正文内容块，按各自流式 ID 和事件序号关联；不把多个块合并后丢掉明细。空白终态块保留在原始事件里，阅读列表隐藏它们。
- 轮次与请求具有独立展开按钮、摘要和固定行高。请求明细折叠包含推理、正文、工具；失败状态不会被折叠摘要隐藏。搜索保留命中项的请求与轮次位置。
- 请求默认打开概览：模型、生成编号、HTTP 请求编号、结束原因、逐次 Token、首内容延迟、输出事件窗口和明细导航。工具和请求可双向定位。
- 请求上下文比较实际消息的共同前缀，区分沿用与新增/变更；完整工具结果消息能通过 `tool_call_id` 返回原调用。比较中发现消息替换就明确标记，不把它伪装成纯追加。
- 工具详情展示参数生成、完整参数事件、执行开始与结束，精确到毫秒。参数流和执行钩子独立上报，按实际时间排序并说明交错。大型结构化结果按需展开，每次最多追加 50 项。
- 后端新增类型化 `data-tool-start`、`data-model-step`；模型步骤的用量在步骤结束时持久化，不必等待整个运行。工具开始事件能在结束事件缺失时保留实际开始边界。两类事件透传至 OpenAPI / SDK。
- 已显示的所有轮次自动读取 500 条之后的事件，避免较早长轮次要点击后才完整。

## 真实验收

本地会话 `ac31a025-941a-46f2-900d-6a97bb92d19a` 的第三轮 `c2fb9923-b9fe-4aa4-a171-c02b68b2ba35`：

- 合成订单 DETAIL-001 = 3、DETAIL-002 = 7；脚本返回 count = 2、total = 10。
- 345 个事件，两次模型请求，一次 `run_skill_script`。
- 请求序号为 1、82；逐步骤用量事件序号为 81、341。因此第一步用量确实在第二次请求开始前保存。
- 第一步输入 2584 / 输出 156 / 总计 2740，结束原因为 tool-calls；第二步输入 2990 / 输出 253 / 总计 3243，结束原因为 stop。
- 工具开始/结束事件序号 77 / 79，调用 ID 一致，执行耗时 419 ms。
- 浏览器验证请求→工具、模型上下文→原工具结果、URL 定位与刷新恢复。
- 三轮完整导出含 993 个事件、7 次请求、10 个内容块、4 次工具调用；逐轮序号和原始 chunk 与数据库全部一致。28 个列表行在指针进入并点击已选请求后，位置和行高变化均为 0 px。

## 边界

这还不等同于 DSH 的全部可观测能力。平台当前未提供 DSH 的 `run_code` 子工具调度协议，因此不会把一次脚本执行捏造成多个子调用；一层子代理执行与父子轨迹已在后续实现，见 [子代理执行与完整父子轨迹](subagent-execution-and-trace-2026-09-12.md)。授权决策的过程记录和上下文压缩事件仍需对应执行机制提供真实事件。

首内容延迟与输出速率来自 Runtime 收到的非空内容事件，是观察窗口；HTTP 首字节单独显示，不宣称它是供应方的首 Token。历史未记录的用量、推理、执行开始和嵌套关系继续保持未知。

验证：全量 Console 测试 90 项、相关后端测试 24 项通过；额外重跑轨迹投影、交互、分页测试。TypeScript、lint、依赖边界、构建和生成 SDK 一致性检查另见本次 `.scratch/detail-*` 日志。仅本地改动，未提交、推送或发布。
